# 차트·인포그래픽 A–H 제작 명세

**이 파일은 편집 가능한 도형·차트를 제작할 때의 지시서다. 실제 PNG·SVG·PPT를 생성한 결과가 아니다.** 기존 홍보 초안의 8가지 시각 자료를 유지하되 실측 없는 도형이 정량 결과처럼 보이지 않도록 조건을 명시했다.

## 공통 디자인

16:9 슬라이드 기준의 제안 배치다. 밝은 배경, 짙은 글씨, 파란 핵심 강조는 기존 브랜드 방향을 따른다. 제목 한 줄, 시각 자료 하나, 하단 상태·근거 한 줄로 구성한다. 글자는 편집 가능한 텍스트로 남기고, 숫자·라벨은 이미지 생성 모델이 임의로 만들지 않게 한다.

상태 라벨은 `제품 개념도`, `구현 목표`, `동일 빌드 실측`, `사업 가설`, `후속 후보` 중 내용에 맞게 사용한다. 실제 수치가 없을 때 막대 크기·너비·면적으로 우열을 암시하지 않는다.

---

## 차트 A. 문제 인식 — 신청 과정에서 우리가 보려는 장벽

**원래 초안:** 접속→메뉴→입력 이해→입력→동의→완료 퍼널.

**현재 근거:** 가족 경험과 절차상의 어려움. 단계별 이탈 수·이탈 원인 비교 없음.

### 현재 사용할 형태
같은 폭의 과정 카드 6개를 수평 또는 두 줄로 배치한다.

```text
서비스 접속 → 메뉴 탐색 → 입력 이해
                              ↓
처리 확인   ← 동의·제출 ← 정보 입력
```

각 카드 아래 ‘확인할 것’을 붙인다: 탐색 시간, 의미 질문, 오류, 확인 여부, 완료 상태. **이탈률이 아래로 커진다고 표시하지 않는다.**

### 슬라이드 제목
**원하는 일과 완료 사이에, 사용자가 해석해야 하는 단계가 있습니다.**

### 실측 후 퍼널로 바꾸는 조건
같은 모집단·같은 과제에서 각 단계 진입/완료와 이탈 정의를 기록한다. 각 단계 인원·분모·기간·도움 조건을 표시한다. 비율만 만들거나 예시 인원으로 채우지 않는다.

**하단:** `개념도 · 단계별 이탈률은 미측정`.

---

## 차트 B. Before / After — 같은 서비스, 다른 화면 구성

### 형태
좌우 48%씩, 가운데 전환 표시. 왼쪽 원본, 오른쪽 FLECTO. 동일한 과제·상태·실제 빌드의 캡처를 사용한다.

### 강조점
왼쪽에 과도한 공포색·비난 문구를 쓰지 않는다. 오른쪽에는 현재 단계, 관련 입력, 원문 보기, 실제 제출을 가리키는 최소 주석만 붙인다.

### 캡처가 없을 때
동일 크기 칸 두 개에 `원본 화면 캡처 예정`, `FLECTO 화면 캡처 예정`을 표시한다. 개념 와이어프레임을 쓰면 `UI 개념도 · 기능 검증 화면 아님`을 붙인다.

**하단:** `같은 과제·상태 / 빌드 [실측값 넣기: BUILD_ID] / [실측값 넣기: DEMO_MODE]`.

---

## 차트 C. 경험 설계 — FLECTO가 줄이고자 하는 세 부담

### 형태
같은 크기 카드 3개. 측정값 없는 레이더·점수 차트는 쓰지 않는다.

| 카드 | 설계 요소 | 확인할 지표 |
|---|---|---|
| 인지 부담 | 현재 작업·관련 입력·짧은 단계 | 도움 요청·이해 질문 |
| 조작 부담 | 큰 버튼·명확한 레이블·입력 안정성 | 오선택·수정·실제 완료 |
| 확인 부담 | 원문·실제 값 검토·명확한 제출 | 제출 내용 이해·결과 확인 |

### 제목
**더 명확하게 보고, 직접 확인하도록 설계합니다.**

‘부담 70% 감소’처럼 실측 없는 개선치를 넣지 않는다. 심리 부담이 줄었다는 문장은 실제 조사 후에만 쓴다.

**하단:** `설계 목표 · 사용자 효과는 미검증`.

---

## 차트 D. 기대효과와 결과 — 더 쉽게, 더 끝까지, 더 스스로

### 실측 전
세 개 KPI 카드의 제목은 `완료`, `도움`, `시간`으로 하고 값은 `측정 예정`이다. 어떤 방식으로 측정할지 한 줄을 넣는다.

### 실측 후
비율만 크게 쓰기보다 `원본 완료 수 / 전체 시도 수`, `실패·timeout 수`, `조건별 준비 시간`을 함께 표기한다. 참가자 체험은 사람 단위로, 자동 반복은 실행 단위로 분리한다.

준비 시간 비교에는 cold/warm/vision을 별개 조건으로 표시한다. 가능하면 각 관측값을 보여주는 점이나 표를 쓰고, 작은 표본의 p95를 대표 성능처럼 제시하지 않는다.

**하단:** `대상·조건·시도 수·실패·도움 제공 여부를 포함`.

---

## 차트 E. 수익구조 — 비개인화 후원과 운영비

### 형태
같은 크기 세 블록: `후원사 후보` → `FLECTO 운영` → `이용자 경험`. 돈 흐름과 기능 흐름은 선 종류와 라벨로 구분한다. 선 굵기로 매출 규모를 암시하지 않는다.

### 도형 문구
- 후원사: 계약 성립 시 후원비·정산 가능한 광고비.
- FLECTO: 신규 분석·검증·재사용·지원.
- 이용자: 별도 구독 부담을 줄이는 방향.

하단 별도 박스: `실제 준비 3초 초과에만 표시 / 완료·취소·10초 종료 시 제거 / 개인 신청 정보 타기팅 없음`.

### 함께 표시할 긴장
`재사용 ↑ → 대기 ↓ → 추론·광고 기회 모두 변화 가능`이라는 설명을 넣는다. 매출 상승 곡선을 만들어내지 않는다.

**하단:** `사업 가설 · 실제 후원 계약·매출 미검증`.

---

## 차트 F. 수익모델 비교 — 적합도 점수 대신 검증할 조건

### 형태
4행 비교표. 직전 초안의 구독·광고·기관 도입·화이트라벨 범주를 유지한다.

| 후보 | 비용 부담자 | 장벽·검증 질문 | 현재 위치 |
|---|---|---|---|
| 사용자 구독 | 이용자 | 초기 진입 부담·지불 의사 | 현재 주력 선택 아님 |
| 광고·후원 | 실제 계약한 후원사 | 대기 감소와 광고 수입의 관계·개인화 없는 가치 | 초기 검토 모델 |
| 기관 도입 | 운영기관 | 반복 문의·도입 책임·실제 지원비 | 중기 후보 |
| SDK·화이트라벨 | 서비스 제공자 | 지원 범위·배포·버전·품질 관리 | 장기 후보 |

### 제목
**누가 어떤 가치에 비용을 지불할 것인가?**

‘낮음/중간/높음’ 적합도나 별점은 현재 조사 결과가 아니므로 사용하지 않는다.

**하단:** `수요·가격·계약은 검증 전`.

---

## 차트 G. 시장 진입 — 업무를 먼저 좁히기

### 형태
세 단계 세로 카드: `검증 환경 → 제한 파일럿 → 반복 가능한 도입`. 각 단계 아래 대상과 증거를 붙인다.

- 검증 환경: 구매 혜택·문화센터 테스트 사이트 / 원본 저장·변형·실패.
- 제한 파일럿: 협의된 신청형 기관 업무 / 사용자·운영 담당자·동의·범위.
- 반복 도입: 검증된 업무 유형 확대 / 유지비·사이트 변경·지원 절차.

### 제목
**한 업무의 정확한 완료에서, 반복 가능한 도입으로.**

실제 협약 기관 로고·지도·고객 수가 없으면 넣지 않는다. ‘학교·복지·교육’은 접촉 가능한 후보군의 예시일 뿐 계약 고객이 아니다.

**하단:** `진입 계획 · 고객 확보 실적 아님`.

---

## 차트 H. 발전 로드맵 — 단계와 진입 조건

### 형태
네 단계 가로 타임라인 또는 카드. 달력 날짜 대신 조건을 표시한다.

| 단계 | 계획 | 진입·완료 근거 |
|---|---|---|
| MVP | 두 사이트·템플릿·원본 연결 | 실제 기능·안전·지연 검사 |
| 사용자 적응·호환성 | 대상 사용자 평가·추가 유형 | 실제 관찰·오류·지원 범위 |
| 기관 도입 | 관리·변경 감지·파일럿 | 수요·책임·운영 비용 검증 |
| 플랫폼 후보 | SDK·화이트라벨·다른 환경 | 반복 도입과 별도 배포 검증 |

### 제목
**검증한 만큼 확장합니다.**

현재 표시를 ‘문서·개발 준비’로 두고, 개발이 완료된 뒤 실제 단계로 바꾼다. 학습 모델·모바일·키오스크를 이번 MVP의 지원 기능처럼 표시하지 않는다.

**하단:** `조건부 발전 방향 · 출시 일정 미정`.

## 제작 우선순위와 금지사항

먼저 B(실제 화면), E(수익구조), H(로드맵), A(문제 과정)를 준비한다. C·D·F·G는 발표 길이에 맞춰 선택한다. 실제 기능 캡처는 검증된 빌드 이후에만 채운다.

이 파일의 차트 수는 8개지만 모두 통계 차트가 아니다. 개념도·카드·비교표·시간 조건도 포함한다. 자료가 없는데 가짜 값·오차막대·정확도·시장 크기를 생성하지 않는다. 외부 조사 데이터를 추가하려면 출처·기준일·표본을 따로 검증하고 원래 자료와 구분한다.
