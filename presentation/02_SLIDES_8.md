# 8장 압축 발표 문안

**짧은 발표용 대안. 12장 원고와 동시에 발표하지 않는다. 실측·캡처가 없으면 목표형 문장을 쓴다.**

## 1. 표지

**Project FLECTO — 복잡한 웹을, 직접 다룰 수 있는 화면으로.**

Don’t bend the user. Bend the interface.

발표 메모: AI는 사용자를 대신해 결정하기보다 현재 필요한 입력과 선택을 보기 쉬운 화면으로 준비하도록 설계했습니다.

## 2. 문제와 동기

**신청 하나를 위해 웹사이트의 메뉴부터 배워야 했습니다.**

가족의 구매 혜택 신청 도움 요청 경험 → 메뉴 찾기·입력 이해·동의·결과 확인.

발표 메모: 가족의 실제 경험에서 시작했으며 전체 고령층의 이탈률 통계로 일반화하지 않습니다. 같은 폭의 과정 카드를 쓰고 수치형 퍼널은 실측 전에는 쓰지 않습니다.

## 3. FLECTO의 선택

**설명이나 대행만이 아니라, 직접 쓰는 새 화면.**

큰 글씨·큰 버튼 / 관련 입력 묶음 / 원문 확인·직접 제출.

발표 메모: 다른 접근이 나쁘다는 것이 아니라 직접 확인하며 진행하는 경험을 목표로 합니다. 사전 설정을 적용하며 행동 학습 모델이라고 소개하지 않습니다.

## 4. 작동 원리

**페이지 구조 → 템플릿 연결 → 검증 → 사용자 조작 → 원본 처리**

재사용은 현재 원본과 대조한 뒤에만.

발표 메모: AI는 짧은 설계안을 만들고 프로그램은 실제 연결·필수 항목·현재 문서를 확인합니다. 임의 코드를 생성해 실행하는 방식으로 소개하지 않습니다.

## 5. 데모와 차별화 증거

**구매 혜택에서 문화센터까지 같은 조작 방식.**

원본 결과 확인 / 준비된 현재 화면의 추가 계획 요청 차단 / 구조 변경 시 연결 거부.

시연 라벨: [실측값 넣기: DEMO_MODE]

발표 메모: 두 사이트는 테스트 서비스입니다. 실제 확인한 범위를 소개하고, 미완성이라면 같은 문장을 완료형으로 쓰지 않습니다. 자세한 전환은 [큐시트](04_DEMO_CUE_SHEET.md)를 사용합니다.

## 6. 기대효과와 확인한 결과

**더 쉽게 · 더 끝까지 · 더 스스로**

실측 전: 완료·오류·도움·준비 시간을 측정할 계획.

실측 후: [실측값 넣기: VERIFIED_RESULTS_WITH_FAILURES]

발표 메모: 참가자 체험과 고령자 검증을 구분합니다. 기능 테스트 숫자를 사용자 만족도로 바꾸지 않습니다.

## 7. 수익과 발전 방향

**실제 준비 중 후원으로 비용 지원을 검토합니다.**

3초 넘게 준비 중일 때만 광고 / 완료·취소·10초면 종료 / 개인정보 타기팅 없음.

두 사이트 검증 → 대상 사용자·기관 파일럿 → 관리 기능·SDK 후보.

발표 메모: 시연 광고이며 계약·매출은 미검증입니다. 대기가 짧아지면 광고 기회도 줄어들 수 있어 운영비와 함께 검증합니다. 단계별 확장은 조건부 계획입니다.

## 8. 마무리

**AI가 화면을 준비하고, 사용자가 직접 결정합니다.**

Project FLECTO — Don’t bend the user. Bend the interface.

발표 메모: 현재 제품 등급과 미검증 범위에 맞춰 마무리합니다. 실제로 없는 URL·무료 가입·상용 배포를 안내하지 않습니다.
