# 12장 표준 발표 — 슬라이드 문안·배치·발표자 메모

**전체 논리:** 문제 → 공감 → 왜 이 방향인가 → 기존 접근과의 관계 → 솔루션 → 구조 → 데모 → 차별점 → 기대효과/결과 → 수익 → 발전 → 마무리.

이 문서는 PPT로 옮길 수 있는 원고다. 현재 제품 성공과 실측은 확인되지 않았으므로 완료형 문장은 조건부다. ‘슬라이드 본문’만 화면에 올리고 제작 메모·검증 조건은 발표자 노트로 둔다.

## 01. 표지

### 슬라이드 본문
**Project FLECTO**

**복잡한 웹을, 직접 다룰 수 있는 화면으로.**

Adaptive Web Runtime

Don’t bend the user. Bend the interface.

### 배치
왼쪽 큰 프로젝트명과 한 줄. 오른쪽 같은 크기의 ‘원본 메뉴 → 목표 중심 화면’ 개념도. 실제 화면이면 캡처 출처·모드를 표시하고, 개념도이면 하단에 ‘제품 개념도’라고 표시한다.

### 발표자 메모
FLECTO는 사용자가 웹사이트의 메뉴 구조를 배우는 대신, 필요한 입력과 선택이 보이는 화면을 제공하고자 하는 프로젝트입니다. AI는 화면을 준비하고 사용자는 직접 확인하며 진행합니다.

### 근거와 제한
[제품 개요](../04_MASTER_OVERVIEW.md). ‘누구나 모든 사이트 지원’ 문구는 쓰지 않는다.

## 02. 문제 — 원하는 것은 신청 하나였습니다

### 슬라이드 본문
**신청은 하나, 먼저 이해해야 할 것은 여러 메뉴.**

가족이 구매 혜택 신청 중 도움을 요청한 경험에서 출발했습니다.

메뉴 찾기 → 입력 의미 이해 → 정보 입력 → 동의·제출 → 결과 확인

### 배치
상단 경험 요약, 아래 같은 폭의 다섯 과정 카드. 그래프처럼 줄어드는 너비·이탈률·가상 사용자 인원은 넣지 않는다.

### 발표자 메모
저희 가족은 온라인 구매 혜택을 신청하다가 어디로 들어가고 무엇을 입력해야 하는지 몰라 도움을 요청했습니다. 관찰한 것은 가족의 경험입니다. 이 사례에서 메뉴 탐색과 입력 절차를 사용자가 직접 이해하기 쉽게 만들 수 있을지 질문했습니다.

### 근거와 제한
멘토링 04:15, [동기 문서](../project/00_MOTIVATION_AND_MENTORING.md). 정확한 혜택 금액·기업 행사 조건·이탈 통계는 없음.

## 03. 왜 이 방향인가 — 설명뿐 아니라 작업 구조

### 슬라이드 본문
**더 많은 설명보다, 지금 필요한 선택을 보여주는 화면.**

- 고령자를 먼저 고려한 큰 글씨와 큰 버튼.
- 관련 입력을 짧은 단계로 묶기.
- 원문을 확인하고 직접 결정하기.

### 배치
기능 카드 세 개. 아이콘은 장식일 뿐 수치 효과나 인증 배지처럼 사용하지 않는다.

### 발표자 메모
FLECTO는 사용자의 능력을 단정하기보다 화면이 요구하는 탐색과 해석을 줄이는 방향을 택했습니다. 현재 단계에서 필요한 입력을 보여주고, 중요한 안내는 원문과 함께 확인하도록 설계했습니다. 실제로 쉬워졌는지는 대상과 조건을 밝힌 평가가 필요합니다.

### 근거와 제한
[UI/UX](../spec/05_UI_UX.md). ‘디지털 이탈의 주원인은 복잡성’이라는 외부 인과 주장으로 확대하지 않는다.

## 04. 기존 접근과 FLECTO의 선택

### 슬라이드 본문
**우리가 바꾸려는 것은 답변이 아니라 조작 화면입니다.**

| 초점 | 접근 |
|---|---|
| 정보를 이해하는 도움 | 설명·읽기·보기 방식 지원 |
| 일을 맡기는 경험 | 행동 자동화 |
| FLECTO | 사용자가 직접 다루는 목적 중심 화면 |

### 배치
같은 크기 세 카드 또는 위 표. 다른 도구를 ‘낮음·없음’으로 표시하지 않는다.

### 발표자 메모
정보 설명이나 자동 대행이 적합한 상황도 있습니다. 저희는 직접 내용을 확인하고 선택하려는 사람에게 일관된 화면을 제공하는 데 집중합니다. 제품군 전체의 성능 우열이 아니라 선택한 사용자 경험의 차이입니다.

### 근거와 제한
[포지셔닝](../project/01_POSITIONING_AND_DIFFERENTIATION.md). 현재 경쟁 제품 전체를 조사한 비교표가 아님.

## 05. 솔루션 — 같은 서비스, 다른 인터페이스

### 슬라이드 본문
**큰 글씨·큰 버튼·쉬운 단계. 실제 처리는 원래 서비스에서.**

사용자 목표 → 필요한 입력·선택 → 직접 확인·제출

### 배치
같은 과제·상태의 실제 원본과 FLECTO 캡처를 좌우에 둔다. 상태가 다르면 설명한다. 없으면 두 칸에 ‘실제 캡처 전 / 개념도’로 표시한다.

### 발표자 메모
새 서비스를 복제하는 것이 아닙니다. 원본 페이지를 유지한 채 새로운 화면을 올리고, 사용자의 입력과 클릭을 원래 기능에 연결하는 구조입니다. 비밀번호는 읽지 않으며 원본 사이트에서 로그인한 뒤 사용하도록 설계합니다.

### 검증 후 바꿀 문장
원본 저장을 확인한 뒤에만 ‘이 화면에서 수행한 신청이 원본 서비스에 저장되었습니다’라고 말한다.

## 06. 작동 방식 — AI는 짧게 설계, 프로그램은 검증

### 슬라이드 본문
**페이지 이해 → 템플릿 연결 → 검증 → 직접 조작 → 원본 결과**

공통 템플릿 6개 · 페이지별 연결 계획 · 검증된 구조 재사용

### 배치
다섯 단계 흐름도. ‘검증된 구조 재사용’에서 계획 단계로 돌아오는 별도 선을 둔다. 개인 입력은 브라우저에 남는 영역으로 구분한다.

### 발표자 메모
UI 코드를 매번 생성하지 않습니다. 미리 만든 템플릿에 현재 페이지의 실제 요소를 연결하는 짧은 계획을 만듭니다. 필수 입력과 안내, 문서 상태와 실행 대상을 프로그램이 검사하고, 사용자는 직접 입력하고 제출합니다. 같은 구조는 현재 페이지와 다시 대조한 뒤 재사용합니다.

### 근거와 제한
[계약](../spec/02_CONTRACTS.md), [Codex·캐시](../spec/04_PLANNER_CACHE_AND_DEADLINES.md). 구조·템플릿 존재는 구현 완료 증거와 다름.

## 07. 데모 — 구매 혜택에서 문화센터까지

### 슬라이드 본문
**서로 다른 사이트에서 같은 조작 방식을 검증합니다.**

구매 혜택: 메뉴 → 주문 정보 → 동의 → 신청

문화센터: 강좌 → 시간 → 확인 → 신청

현재 시연 모드: [실측값 넣기: DEMO_MODE]

### 배치
실제 브라우저 화면을 크게 사용한다. 발표 슬라이드는 시연 전 체크리스트 역할만 하며 실제 서비스명으로 오인시키는 로고는 쓰지 않는다.

### 발표자 메모
두 원본 서비스는 가상의 테스트 사이트입니다. 이번 시연은 [실측값 넣기: VERIFIED_SCOPE]를 확인한 빌드입니다. 새 화면의 완료 표시뿐 아니라 원본 신청 결과를 함께 확인하겠습니다.

### 미완성 대체 문장
현재 구매 혜택의 [확인한 범위]까지 확인했으며 문화센터는 [미완성 범위]가 남아 있습니다. 이어지는 화면은 [고정 응답 시연 / 개념도 / 녹화]입니다.

### 진행표
[데모 큐시트](04_DEMO_CUE_SHEET.md). LIVE·CACHE·FIXTURE·REPLAY를 가리지 않는다.

## 08. 차별점 — 준비된 화면은 직접 조작

### 슬라이드 본문
**계획 이후의 반복 조작까지 AI에게 맡길 필요는 없도록.**

- 준비된 현재 화면의 입력·수정·제출.
- 두 사이트의 일관된 템플릿.
- 원본 변경 시 오래된 연결 거부.

### 배치
‘AI 준비’와 ‘사용자 조작’ 영역을 분리한 구조도. 실제 검증했을 때만 ‘이 화면에서 추가 계획 요청 [실측값]회’를 표시한다.

### 발표자 메모
차별점은 광고나 확인 버튼 하나가 아닙니다. AI가 준비한 화면을 사용자가 직접 반복 조작하고, 그 화면의 기능을 일반 코드로 연결하는 구조입니다. 페이지가 바뀌면 재분석이 필요합니다. 현재 화면의 추가 계획 요청만 차단해도 원본 동작이 이어지는지를 확인합니다.

### 근거와 제한
[차별점](../project/01_POSITIONING_AND_DIFFERENTIATION.md). 모든 에이전트보다 싸고 안전하다는 비교 주장은 하지 않는다.

## 09. 기대효과와 실제 결과

### 실측 전 슬라이드 본문
**더 쉽게, 더 끝까지, 더 스스로 — 검증할 세 가지 목표.**

- 작업 완료와 오류.
- 도움 요청과 실제 이해.
- 준비 시간·재사용·실패.

현재: 실측 결과 미확보 / 고령자를 고려한 설계, 실제 대상자 효과는 미검증.

### 실측 후 본문 교체안
전체 시도 [실측값 넣기: TOTAL_ATTEMPTS] / 원본 완료 [실측값 넣기: SUCCESS_COUNT] / 실패·timeout [실측값 넣기: FAILURE_COUNT]

### 배치
실측 전은 같은 크기 카드 세 개. 실측 후는 표본 수·실패를 함께 표시한 표 또는 실제 분포. 데이터 없이 막대 높이를 만들지 않는다.

### 발표자 메모
기술 검사와 사람의 사용 경험은 다릅니다. 심사위원과 참가자 체험은 그 범위를 밝혀 보고하고, 고령자 전체의 효과로 일반화하지 않겠습니다. 현재 자료가 없으면 목표와 측정 계획을 설명합니다.

### 근거

## 10. 수익구조 — 빠르게 끝날수록 먼저 사라지는 광고

### 슬라이드 본문
**이용자 비용을 지원하는 비개인화 후원 모델을 검토합니다.**

3초 초과의 실제 준비 중 → 구분된 후원 카드

준비 완료·취소·10초 종료 → 즉시 제거

초기 후원 → 기관 도입 후보 → SDK·화이트라벨 후보

### 배치
사용자·FLECTO·후원사의 관계도와 시간 조건 카드. 화살표를 실제 계약 매출 흐름이 아니라 사업 가설로 표시한다.

### 발표자 메모
현재는 시연 광고이며 실제 계약이나 매출이 없습니다. 광고를 보기 위해 기다리게 하지 않고, 신청 정보를 타기팅에 쓰지 않습니다. 재사용으로 대기가 줄면 광고 기회도 줄 수 있어 노출 기반 모델과 기간 후원, 후속 기관 도입 수요를 검증하려 합니다.

### 근거와 제한
[수익모델](../business/00_REVENUE_MODEL.md). 시연 표시 횟수와 광고 정산을 구분한다.

## 11. 발전 방향 — 검증된 단계마다 범위를 넓히기

### 슬라이드 본문
**MVP → 사용자·호환성 검증 → 기관 파일럿 → 서비스 내장형 확장**

현재: 두 절차형 서비스와 검증·복구 구조

다음: 대상 사용자 경험과 운영 비용 확인

장기: 관리 도구·SDK·다른 인터페이스 환경 검토

### 배치
날짜 없는 네 단계 로드맵. 각 단계 아래 진입 조건 한 줄. 미정 분기별 출시·매출 목표를 넣지 않는다.

### 발표자 메모
우선 두 사이트의 정확한 동작을 확인하고, 그다음 실제 대상 사용자와 기관 파일럿을 통해 사용성과 유지 비용을 검증할 계획입니다. 모바일이나 키오스크, 자체 모델은 별도 개발·검증이 필요한 후속 후보입니다.

### 근거
[진입·로드맵](../business/01_GTM_AND_ROADMAP.md).

## 12. 마무리

### 슬라이드 본문
**AI가 화면을 준비하고, 사용자가 직접 결정합니다.**

Project FLECTO

Don’t bend the user. Bend the interface.

### 배치
큰 결론 한 줄과 이름. 실제 연락처·공개 주소가 없으면 가짜 QR·가입 버튼을 넣지 않는다.

### 발표자 메모
FLECTO는 복잡한 메뉴 대신 필요한 선택에 집중할 수 있는 화면을 목표로 합니다. 구현한 범위는 실제 원본 결과로 확인하고, 아직 검증하지 않은 효과는 앞으로 검증하겠습니다. 사용자가 웹사이트에 적응하는 대신 인터페이스가 사용자에게 맞춰지도록 하겠습니다.

### 제출 전
[공개 점검표](../evidence/02_PUBLISH_CHECKLIST.md)와 현재 제품 등급을 확인한다. 발표 문장이 실제 결과보다 앞서가지 않게 한다.
