# 발표 패키지 사용법

**대상: 대회 발표·질의응답·심사위원 체험·홍보 자료 제작. 현재는 문안과 제작 명세이며 슬라이드 파일·렌더된 차트·영상은 없다.**

## 1. 세 가지를 함께 준비한다

**짧은 스토리:** 가족 경험 → 원하는 일과 복잡한 메뉴 사이의 문제 → FLECTO.

**실제 증거:** 원본 신청 결과, 준비된 화면의 추가 계획 요청 차단, 두 사이트, 구조 무효화.

**사업·확장:** 후원 광고는 검증할 수익 가설, 기관·SDK는 단계 조건이 있는 후속 후보.

## 2. 파일 선택

| 사용할 상황 | 문서 |
|---|---|
| 표준 원고 | [12장 슬라이드](01_SLIDES_12.md) |
| 짧은 발표·시간 축소 | [8장 압축 슬라이드](02_SLIDES_8.md) |
| 발표자가 읽을 대본 | [3·5·7분 대본](03_SCRIPTS_3_5_7.md) |
| 실제 시연 순서와 장애 대응 | [데모 큐시트](04_DEMO_CUE_SHEET.md) |
| 예상 반론 | [20개 Q&A](05_JUDGE_QA_20.md) |

| 한 장 소개·게시글 | [홍보 원고](../marketing/01_ONEPAGER_AND_PROMO.md) |

12장과 8장은 내용의 길이를 선택하는 대안이다. 둘을 모두 발표하지 않는다. 3·5·7분은 공식 발표 시간이 아니라 리허설용 구성이다.

## 3. 기본 상태와 문안 선택

현재 제품 실행은 미확인이므로 ‘설계했다 / 구현 목표다 / 검증할 계획이다’가 기본이다. 실제 데모를 할 때에는 [결과 양식](../evidence/01_RESULTS_TEMPLATE.md)을 실제 자료로 채우고, 같은 빌드의 검증 범위를 확인한 뒤 완료형 문장을 선택한다.

| 확보 상태 | 사용 방식 |
|---|---|
| FULL_LIVE | 확인한 두 사이트·검사 조건을 명시하고 실제 시연 |
| LIMITED_LIVE | 확인한 두 사이트 DOM 경로를 설명하고 미완성 기능 공개 |
| SINGLE_SITE_LIVE | 구매 혜택 데모만 완료형, 문화센터는 확장 목표 |
| FIXTURE_ONLY | 고정 모델 응답 기반 기능 시연이라고 표시, LIVE 아님 |
| UNVERIFIED | 기획·구현 중인 범위 설명. 완성 동작·수치 주장 금지 |

자료가 없을 때 쓰는 대체 문장은 각 슬라이드와 대본에 있다. 실패한 제품을 성공한 것처럼 숨기라는 의미가 아니다.

## 4. 외형 원칙

밝은 배경·짙은 글씨·파란 핵심 행동의 기존 방향을 유지한다. 한 장에 메시지 하나, 실제 화면이나 간단한 구조도 하나를 우선한다. 도형 안 긴 문단·작은 각주·장식성 3D 차트를 피한다. 수치·정책·현재 경쟁사 설명에는 근거와 기준일이 필요하다.

준비된 증거가 없을 때 차트는 개념도·측정 항목·기대효과로 표시한다. 임의 가짜 막대·퍼널 비율·별점·시장 규모를 넣지 않는다.

## 5. 제출 전 작업 순서

1. 현재 제품 등급·검증 빌드 확인.
2. 실제 시간에 맞게 12장/8장과 대본 길이 선택.
3. 실제 캡처·표본·실패·모델 설정 연결.
4. 빠진 지표는 ‘미측정’ 또는 검증 계획 문장으로 대체.
5. [주장표](../evidence/00_CLAIM_LEDGER.md)와 [공개 점검표](../evidence/02_PUBLISH_CHECKLIST.md) 확인.
6. 실제 발표·전환·데모를 리허설하고 시간 조정.

공식 발표 분량·배점·제출 채널은 현재 자료에서 확정값으로 넣지 않았다. 새로운 요구사항이 생기면 제품의 필수 안전 동작을 빼지 않고 발표 범위를 조정한다.
