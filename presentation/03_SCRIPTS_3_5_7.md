# 3분·5분·7분 발표 대본

**분량은 리허설 목표다. 공식 발표 시간이나 실제 발화 시간을 측정한 결과가 아니다.** 각 대본은 예상 전환·데모 시간을 포함한 구성이다. 실제 리허설에서 조정하고, 숫자와 완료형 표현은 동일 빌드의 근거를 얻은 뒤 사용한다.

현재는 계획·문안 단계다. `[시연]` 구간은 실제 검증한 화면이 준비된 경우에만 수행한다. 없으면 ‘현재 구현 목표이며 이 화면은 개념도/고정 응답 시연’이라는 대체 문장을 사용한다.

---

## A. 3분 구성

### 시간 배분안
문제 30초 / 해결 30초 / 시연 55초 / 차별점 25초 / 사업·발전 25초 / 마무리 15초 = 180초.

### 원고

**[문제]**
Project FLECTO를 소개합니다. 저희 가족은 온라인 구매 혜택을 신청하다가 어떤 메뉴로 들어가고 무엇을 입력해야 하는지 몰라 도움을 요청했습니다. 원하는 것은 신청 하나였지만, 먼저 웹사이트의 구조를 이해해야 했습니다. FLECTO는 이 경험에서 출발했습니다.

**[해결]**
저희는 설명을 더하는 것뿐 아니라 직접 사용할 수 있는 화면을 만드는 방향을 택했습니다. 큰 글씨와 큰 버튼, 짧은 입력 단계로 필요한 선택을 보여줍니다. AI는 현재 페이지를 공통 템플릿에 연결하는 계획을 만들고, 프로그램이 원본 기능과 맞는지 확인합니다. 사용자가 직접 입력하고 동의하고 제출합니다.

**[시연 안내]**
지금부터 보여드릴 범위는 [실측값 넣기: VERIFIED_SCOPE]이며, 시연 모드는 [실측값 넣기: DEMO_MODE]입니다. 원본 메뉴에서 목표를 선택하고, 필요한 정보를 입력하고, 원본 신청 결과까지 확인하겠습니다.

**[약 55초 시연 — 실제 원본 결과 확인을 우선한다.]**

**[차별점]**
대신 처리하는 것이 목적이라면 에이전트도 적합합니다. FLECTO는 준비된 화면에서 직접 선택하고 수정하는 경험에 집중합니다. 검증된 현재 화면에서는 반복 조작마다 새 계획을 요청하지 않는 구조이며, 두 사이트에 같은 조작 방식을 적용하는 것을 목표로 합니다.

**[사업·발전]**
실제 준비가 3초를 넘을 때 표시하는 비개인화 후원 카드로 비용을 지원하는 모델을 검토합니다. 준비되면 바로 사라지며 현재는 시연 광고입니다. 이후에는 대상 사용자와 기관 파일럿으로 사용성과 운영비를 검증할 계획입니다.

**[마무리]**
AI가 화면을 준비하고, 사용자가 직접 결정합니다. 복잡한 메뉴 대신 필요한 선택에 집중할 수 있도록, Project FLECTO입니다.

## B. 5분 구성

### 시간 배분안
문제·동기 40초 / 제품 45초 / 구조 35초 / 시연 90초 / 결과·차별점 40초 / 수익·발전 35초 / 마무리 15초 = 300초.

### 원고

**[문제·동기]**
저희가 FLECTO를 생각한 계기는 가족의 구매 혜택 신청이었습니다. 어떤 메뉴를 눌러야 하는지, 주문 정보를 어디에 넣어야 하는지 몰라 도움을 요청했습니다. 이 사례를 전체 고령자의 경험으로 일반화할 수는 없습니다. 다만 사용자가 원하는 일과 웹사이트가 요구하는 탐색 사이에 간격이 있다는 문제를 발견했습니다. 저희는 고령자를 먼저 고려해 그 간격을 줄이는 화면을 만들고자 합니다.

**[제품]**
FLECTO는 기존 웹사이트 위에 큰 글씨·큰 버튼의 단계형 인터페이스를 표시하는 브라우저 확장입니다. 첫 화면에서는 확인된 작업을 큰 버튼으로 보여주고, 다른 목표를 직접 입력할 수도 있게 합니다. 관련 입력은 묶어서 보여주며, 중요한 안내와 동의는 원문을 확인할 수 있도록 유지합니다. 사용자는 AI에게 모든 선택을 맡기지 않고 내용을 확인한 뒤 직접 제출합니다.

**[구조]**
매번 새로운 웹 코드를 만드는 구조는 아닙니다. 미리 준비한 여섯 템플릿에 현재 페이지의 실제 요소를 연결하는 짧은 계획을 만듭니다. 프로그램은 필수 입력과 안내, 실행 대상과 문서 상태를 확인합니다. 기존 구조가 있으면 현재 페이지에 다시 연결해 검사하고 재사용합니다. 실제 개인 입력이나 로그인 정보는 계획·공유 캐시·광고에 보내지 않는 원칙으로 설계했습니다.

**[시연 안내]**
두 원본 서비스는 구매 혜택과 문화센터를 본뜬 가상의 테스트 사이트입니다. 현재 확인한 빌드는 [실측값 넣기: BUILD_AND_SCOPE]입니다. 시연 모드 [실측값 넣기: DEMO_MODE]를 확인해 주세요. 먼저 구매 혜택을 신청하고 원본 결과를 확인한 뒤, 가능한 검증 범위에서 문화센터와 반복 조작을 보여드리겠습니다.

**[90초 시연 — 실패하면 큐시트의 공개된 복구 문장을 사용한다.]**

**[결과·차별점]**
이 제품의 차별점은 확인 버튼 하나나 광고가 아닙니다. AI가 준비한 현재 화면을 사용자가 직접 조작하고, 그 안의 입력·수정·제출을 검증한 코드로 수행하는 데 있습니다. 페이지가 바뀌면 다시 분석하고, 다른 사이트에서도 같은 조작 방식을 사용하도록 설계했습니다.

실측 전 문장: 현재는 원본 저장, 변경 대응, 대기 시간과 실패를 함께 검증하는 단계이며, 사용자 효과 수치를 아직 제시하지 않습니다.

실측 후 교체 문장: 같은 빌드에서 [실측값 넣기: RESULT_SUMMARY_WITH_FAILURES]를 확인했습니다. 체험자는 [실측값 넣기: PARTICIPANT_GROUP]이며, 고령자 전체 효과로 일반화하지 않습니다.

**[수익·발전]**
초기에는 실제 준비 시간이 3초를 넘을 때 표시하는 비개인화 후원 모델을 검토합니다. 광고를 위해 기다리게 하지 않으며 준비 완료나 취소, 10초 상한에 도달하면 사라집니다. 재사용이 늘면 광고 기회도 줄 수 있어 실제 계약 수입과 운영비를 함께 검증해야 합니다. 이후 대상 사용자 검증과 기관 파일럿을 거쳐 내장형 SDK 등으로 확장할 계획입니다.

**[마무리]**
사용자를 웹사이트에 맞추지 않고 인터페이스를 사용자에게 맞추는 것. AI가 화면을 준비하고 사용자가 직접 결정하는 것. Project FLECTO가 목표로 하는 경험입니다.

## C. 7분 구성

### 시간 배분안
동기 50초 / 문제·접근 45초 / 구조 55초 / 시연 110초 / 결과 45초 / 차별점 40초 / 수익·로드맵 55초 / 마무리 20초 = 420초.

### 원고

**[동기]**
FLECTO는 가족이 온라인 구매 혜택 신청 중 도움을 요청한 경험에서 시작했습니다. 어떤 메뉴로 들어가야 하는지, 어떤 번호를 찾아 입력해야 하는지, 빠진 항목이 무엇인지 확인하는 과정이 복잡했습니다. 원하는 일은 하나였지만 웹사이트의 메뉴와 용어를 먼저 이해해야 했습니다. 저희가 실제로 관찰한 것은 이 가족의 경험입니다. 모든 고령자가 같은 어려움을 겪는다고 단정하기보다, 이 상황에서 사용자가 직접 할 수 있는 환경을 만들 수 있을지 질문했습니다.

**[문제·접근]**
정보를 설명하거나 일을 대신 처리하는 접근도 도움이 될 수 있습니다. 하지만 저희는 본인이 내용을 확인하고 선택하려는 사람에게 초점을 맞췄습니다. 큰 글씨와 큰 버튼으로 현재 필요한 입력을 보여주고, 동의와 제출의 의미는 숨기지 않는 방식입니다. 글씨·대비·설명량은 사용자가 사전 설정에서 선택하며, 나이나 장애를 자동으로 추정하지 않습니다. 설정을 적용하는 기능과 사용자의 행동을 학습하는 모델은 구분합니다.

**[구조]**
FLECTO는 원본 페이지를 삭제하거나 서비스의 기능을 대신 구현하지 않습니다. 현재 페이지의 공개 구조를 정리하고, 공통 템플릿에 실제 입력과 버튼을 연결하는 계획을 만듭니다. AI가 임의 HTML이나 JavaScript를 생성해 실행하는 것이 아니라, 정해진 형식의 요소 참조를 반환하는 방식입니다. 그 뒤 프로그램이 필수 항목, 중요한 안내, 원본 폼과 문서 상태를 확인합니다.

사용자의 실제 입력과 최종 검토 내용은 브라우저의 실제 값에서 나옵니다. 로그인은 원본 Chrome 화면에서 테스트 계정으로 하고, 비밀번호를 읽거나 모델에 전달하지 않는 원칙을 유지합니다. 검증한 작업 구조는 로컬에 저장하지만, 다음 사용자의 값이나 예전 강좌 정원은 저장된 사실처럼 가져오지 않습니다.

**[시연 안내]**
현재 시연 빌드는 [실측값 넣기: BUILD_AND_SCOPE]이며 모드는 [실측값 넣기: DEMO_MODE]입니다. 테스트 사이트에서 구매 혜택 신청을 완료하고 원본 결과를 확인하겠습니다. 이후 준비된 현재 화면의 추가 계획 요청만 차단하는 장면, 또는 문화센터에서 같은 템플릿을 사용하는 장면을 검증된 범위에서 보여드리겠습니다.

**[110초 시연 — 제품 준비 10초 실패가 발생하면 즉시 실제 상태를 설명하고 원본 또는 라벨한 녹화로 전환한다.]**

**[결과]**
결과가 있으면: 전체 [실측값 넣기: ATTEMPTS]회 중 원본 완료 [실측값 넣기: COMPLETIONS]회, 실패·timeout [실측값 넣기: FAILURES]회였습니다. 최초 생성과 검증된 재사용은 구분해 측정했고, 조작 가능한 시점까지의 시간은 [실측값 넣기: READY_SUMMARY]입니다. 실제 체험자는 [실측값 넣기: PARTICIPANT_GROUP]입니다.

결과가 없으면: 현재 결과 수치를 제시할 만큼의 검증을 하지 못했습니다. 원본 저장과 필수 정보 보존, 중복 제출, 시간 상한, 한국어 입력과 확대 화면을 검증할 항목으로 정했습니다. 이번 자료는 그 설계와 확인된 구현 범위에 한정됩니다.

어느 경우든: 심사위원·참가자 체험을 고령자 전체의 사용성 증거로 바꾸지는 않습니다. 실제 대상 사용자 평가는 다음 단계입니다.

**[차별점]**
‘그냥 에이전트가 대신 해주면 되지 않나요?’라는 질문에는 사용 경험의 차이로 답하고 싶습니다. 대신 처리하고 싶은 사람에게는 에이전트가 적합할 수 있습니다. 저희는 사용자가 반복해서 선택을 바꾸고 내용을 확인할 수 있는 현재 화면을 만듭니다. 검증된 화면의 반복 조작에는 추가 계획 호출이 필요하지 않도록 하고, 사이트가 달라도 같은 방식을 쓰며, 구조가 바뀌면 오래된 연결을 거부합니다. 다른 도구가 이런 기능을 절대 할 수 없다는 주장이 아니라 이 결합을 제품의 기본으로 삼는 것입니다.

**[수익·로드맵]**
수익은 기술적 차별점과 분리해서 검토합니다. 초기에는 실제 화면 준비가 3초를 넘는 경우 비개인화 후원 카드를 표시하고, 준비되면 즉시 없애는 방식입니다. 현재 광고는 시연용이며 계약이나 매출이 없습니다. 광고를 위해 시간을 늘리면 제품의 목적과 충돌하므로 그렇게 하지 않습니다. 오히려 재사용으로 대기가 줄면 광고 기회도 줄 수 있어 후원 계약과 처리 비용을 함께 봐야 합니다.

이후에는 실제 대상 사용자 경험을 평가하고, 복잡한 신청을 운영하는 기관과 제한적인 파일럿을 검토하려 합니다. 그 과정에서 사용성뿐 아니라 사이트 변경 대응, 데이터 처리와 지원 책임을 확인해야 합니다. 기관 관리 도구·화이트라벨·SDK, 다른 기기 인터페이스는 이 검증을 거친 뒤의 후보입니다.

**[마무리]**
FLECTO의 목표는 사용자의 결정을 없애는 것이 아니라, 그 결정을 하기 어려운 화면을 바꾸는 것입니다. AI는 화면을 준비하고 사용자는 직접 결정합니다. Don’t bend the user. Bend the interface.

## 공통 대체 문장

- 실제 모델 호출 실패: **“지금 실제 모델 연결에서 준비가 끝나지 않았습니다. 원본으로 돌아갈 수 있으며, 이어서 보여드리는 영상은 이전 검증 빌드의 녹화입니다.”** 녹화가 없으면 앞 절반만 말하고 계획으로 전환한다.
- 고정 응답 시연: **“지금은 모델 응답을 고정한 기능 테스트 모드입니다. 실제 모델 성능을 보여주는 시연은 아닙니다.”**
