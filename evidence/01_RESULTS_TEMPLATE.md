# 실제 결과 입력 양식 — 비어 있는 칸을 0으로 채우지 않기

**현재 모든 제품·사용성·매출 값은 미측정 또는 NOT_RUN이다.** 아래는 실행 후 채울 양식이다. 자료 정리 과정의 파일 검사와 제품 검사는 별개다.

## A. 실행과 빌드

| 필드 | 값 |
|---|---|
| run_id / 날짜·시간대 | [실측값 넣기: RUN_ID / RUN_TIME] |
| 소스 커밋 / 빌드 해시 | [실측값 넣기: SOURCE_SHA / ARTIFACT_HASH] |
| 제품 모델 ID·추론 설정·SDK/CLI 버전 | [실측값 넣기: MODEL_LOCK] |
| 개발 클라이언트·모델 | [실측값 넣기: DEVELOPMENT_ENV] |
| 제품 등급 | UNVERIFIED |
| 운영 등급 | DOCS_ONLY |
| LIVE / FIXTURE / CACHE / REPLAY | [실측값 넣기: DEMO_MODE] |
| 실제 제출 | false |

## B. 기능·속도 결과

| 조건 | 전체 시도 | 성공 | 실패·timeout | 조작 가능 시간 중앙/최소/최대 | 근거 |
|---|---|---|---|---|---|
| 구매 혜택 cold LIVE | NOT_RUN | 미측정 | 미측정 | 미측정 | 없음 |
| 구매 혜택 warm | NOT_RUN | 미측정 | 미측정 | 미측정 | 없음 |
| 문화센터 cold LIVE | NOT_RUN | 미측정 | 미측정 | 미측정 | 없음 |
| 문화센터 warm | NOT_RUN | 미측정 | 미측정 | 미측정 | 없음 |
| 시각 보완 | NOT_RUN | 미측정 | 미측정 | 미측정 | 없음 |
| 구조 변경·무효화 | NOT_RUN | 미측정 | 미측정 | 미측정 | 없음 |

기준 시간은 사용자가 목표를 요청한 순간부터 검증된 컨트롤이 실제 조작 가능한 시점까지다. 10초 timeout을 성공 요청의 지연 평균에 숨겨 넣거나 전체 시도에서 빼지 않는다. 성공 사례 지연을 따로 낼 때도 실패 수를 함께 공개한다.

준비 이후 추가 계획 요청 차단 시험:
- 현재 화면·동작: [실측값 넣기: POST_READY_SCENARIO]
- 추가 계획 요청 수: [실측값 넣기: ADDITIONAL_PLAN_REQUESTS]
- 원본 처리 결과: [실측값 넣기: SOURCE_RESULT]
- 페이지 이동/구조변경이 없던 범위인지: [실측값 넣기: SCOPE]

## E. 슬라이드에 넣을 결과 문장

데이터가 있으면:
> 동일 빌드에서 [실측값 넣기: LIVE_ATTEMPTS]회 시도 중 [실측값 넣기: LIVE_SUCCESSES]회 원본 저장을 확인했습니다. 실패 [실측값 넣기: LIVE_FAILURES]회와 timeout [실측값 넣기: LIVE_TIMEOUTS]회가 있었고, 조건은 [실측값 넣기: TEST_CONDITIONS]입니다.

데이터가 없으면:
> 현재는 구현·검증 계획을 제시합니다. 원본 저장, 필수 항목 보존, 준비 시간과 실패를 함께 측정할 예정이며, 실제 효과 수치는 아직 없습니다.

## F. 채우는 담당

QA는 실제 결과 파일과 빌드 근거를 제공한다. 발표 담당은 문안을 선택한다. RELEASE가 수치·시제·라벨을 최종 대조한다. 모델이 빠진 값을 추정해 채우지 않는다.
