# 발표·홍보·출고 전 점검표

**초기 체크는 모두 미완료다. 문서가 있다는 이유만으로 체크하지 않는다.**

## 주장과 근거
- [ ] 목표·구현 완료·실제 검증·미검증·사업 가설을 구분했다.
- [ ] 모든 수치의 조건·시도 수·실패·빌드 해시·근거 파일을 확인했다.
- [ ] 빈 수치를 0이나 그럴듯한 예시 수치로 채우지 않았다.
- [ ] 가족 경험을 실제 인터뷰 문장으로 꾸미거나 전체 고령층으로 일반화하지 않았다.
- [ ] ‘세계 최초’, ‘모든 웹’, ‘100% 안전’, ‘항상 3초’ 표현이 없다.
- [ ] 다른 에이전트 전체의 통제·캐시·확인 기능을 부정하지 않았다.

## 차트와 시각 자료
- [ ] 실측 이탈률 없는 퍼널은 과정도로 표시했다.
- [ ] Before/After는 같은 과제·상태·조건의 실제 화면이며 UI 개념도와 구분했다.
- [ ] 차트 축·단위·표본 수와 실패 처리가 명확하다.
- [ ] 기대효과 카드가 실제 개선률이나 측정된 크기처럼 보이지 않는다.
- [ ] 로드맵은 검증 조건을 표시하고 미정 출시 일정을 약속하지 않는다.

## 제품 데모
- [ ] LIVE CODEX / CACHE / FIXTURE / REPLAY가 화면과 설명에서 일치한다.
- [ ] 원본 서버에 저장된 값과 처리 건수를 확인했다.
- [ ] AI 요청 차단은 현재 화면의 계획 경로에 한정했다고 설명한다.
- [ ] 합성 계정·시연용 Chrome 프로필을 사용한다.
- [ ] 개인정보·토큰·개인 계정·원본 비공개 로그가 영상·파일에 없다.
- [ ] 후원 카드가 준비 완료·취소·10초 만료 뒤 남지 않는다.
- [ ] 지연 주입 시연은 오류 처리 테스트라고 표시한다.

## 사업과 발전
- [ ] 실제 후원 계약이 없으면 시연 광고라는 라벨이 있다.
- [ ] 카드 표시 횟수를 정산 가능한 광고 노출·매출로 바꾸지 않았다.
- [ ] 캐시로 대기가 줄면 광고 기회도 줄 수 있다는 점을 설명한다.
- [ ] 기관 도입·화이트라벨·학습 모델은 후속 후보로 표시했다.
- [ ] 실제 도입·공개 배포·광고 관련 정책 검토를 완료했다고 주장하지 않았다.

## 마감과 권한
- [ ] 발표에 사용할 버전과 현재 release 등급을 맞췄다.
- [ ] 제품이 미완성이면 계획·실제 구현 경계를 구분해 소개한다.
- [ ] 공식 발표 시간·제출 요구사항을 확인했다.
- [ ] 게시·공유·대회 제출은 사용자 승인을 받았다.
- [ ] 실제 제출 확인 전에는 submitted=false를 유지한다.

최종 판정은 `state/PRESENTATION_STATUS.md`에 기록한다. 이 체크리스트는 실제 제품·법률·접근성 인증을 대신하지 않는다.
