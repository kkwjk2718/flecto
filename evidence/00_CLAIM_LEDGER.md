# 발표 주장·출처·검증 상태 표

**현재: 신규 제품 실행 근거 없음. 아래 ‘구현 계획’은 성공 결과가 아니다.**

## 상태 정의

- **사용자 결정:** 현재 대화에서 사용자가 선택한 범위·경험·운영 조건.
- **관찰:** 제공한 전사에서 설명한 실제 경험. 표본·정확한 사실 범위를 제한한다.
- **구현 목표:** spec·검사에 있는 요구사항. 실제 실행 전에는 미검증.
- **기대효과/사업 가설:** 앞으로 사용자·비용·계약 검증이 필요.
- **이전 초안의 미지원 주장:** 이전 문구는 존재하지만 현재 자료에 입증 근거 없음.
- **과거 외부 참조:** 이전 문서에서 링크한 자료. 이번에 재조회하지 않음.

## 직전 발표 초안에서 그대로 쓰지 않을 문장

| 이전 표현 | 왜 현재 자료만으로는 부족한가 | 문서화한 사용안 |
|---|---|---|
| “웹 사용의 이탈은 기능 부족보다 복잡성에서 발생합니다” | 원인별·단계별 이탈 자료 없음 | ‘우리가 해결하려는 장벽은 메뉴와 입력 절차의 복잡성입니다’ |
| “많은 사용자는 로그인 이전이 아니라 실제 신청 단계에서 이탈합니다” | 로그인 대비 이탈 비교가 없음 | ‘신청 단계에서 어디에서 막히는지 관찰하겠습니다’ |
| “일반 AI 에이전트는 사용자 통제가 낮습니다” | 제품마다 다르고 비교 근거 없음 | ‘FLECTO는 직접 조작하는 화면을 중심으로 설계합니다’ |
| “기존 도구는 화면을 그대로 둡니다” | 도구군 전체를 조사하지 않음 | ‘화면 확대·설명만이 아니라 작업 중심 재구성을 목표로 합니다’ |
| “서비스 접근성을 향상했습니다” | 구현·사용자 테스트 전 | ‘접근성 향상을 목표로 설계합니다’ |
| “기관 도입이 가장 현실적입니다” | 시장·계약 검증 없음 | ‘기관 도입은 후속 검증 후보입니다’ |

## 공개 전에 확인

발표 자료·대본·차트의 숫자마다 실측 파일, 빌드 해시, 모델 설정, 표본 수를 연결한다. 근거가 없으면 숫자를 제거하고 검증 항목을 보여준다. 의미 없는 0으로 채우지 않는다. 홍보 문구가 제품 제한·안전 규칙을 바꾸지 않는다.
