# 새 세션·다른 개발 모델에서 재개

1. `AGENTS.md`, `01_DECISIONS.md`, `state/STATUS.md`, `state/NEXT_ACTION.md`, `state/BLOCKERS.md`를 읽는다.
2. 실제 현재 폴더·Git HEAD·dirty diff·활성 프로세스·시간·실행 모드를 확인한다. 세션 기록의 완료 주장을 그대로 믿지 않는다.
3. 현재 사용자 승인과 capability 기록을 확인한다. 새 모델·provider·청구경로를 자동 승인하지 않는다.
4. ledger/작업 세대와 늦은 handoff를 대조한다. 같은 patch를 두 번 합치거나 중단된 source submit을 다시 클릭하지 않는다.
5. 관련 모듈·검사·계약만 읽고 다음 최소 작업을 선택한다. 과거 v2/v3 모델·Windows 사양으로 되돌리지 않는다.
6. 현재 stage가 fixture인지 LIVE인지 확인한다. 모델이 바뀌면 필요한 새 probe와 재검증을 한다.
7. 마감이 지났다면 코드 생성을 다시 시작하지 않고 안전한 현재 결과물 등급·한계를 정리한다.

이전에 실행기가 없었다면 없는 supervisor resume을 호출하지 않는다. 실제 Command Registry에 등록된 명령만 사용한다. 불필요한 확인 질문은 하지 않되 새 권한은 기록된 근거가 있어야 한다.
