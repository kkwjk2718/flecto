# 기대효과와 측정 계획

**아래는 기대효과이지 현재 실증 결과가 아니다.** 이전 초안의 ‘더 쉽게, 더 끝까지, 더 스스로’라는 방향을 유지한다.

## 1. 인지 부담

**가설:** 현재 해야 할 입력과 선택을 묶어 보여주면 메뉴·절차를 해석하는 부담이 줄어들 수 있다.

**설계:** 단계별 제목, 관련 입력 2~3개, 큰 작업 버튼, 필요한 안내와 원문.

**측정:** 첫 적절한 행동까지의 시간, 도움 요청, 되돌아가기, 단계 해석 질문. 단순히 버튼 수가 줄었다고 인지 부담 감소가 입증되는 것은 아니다.

## 2. 조작 부담

**가설:** 큰 버튼·큰 글씨·일관된 위치가 선택과 입력을 돕는다.

**설계:** 사전 표시 설정, 한국어 IME 보존, 키보드·포커스·200% 확대, 잘못된 입력에 문장 안내.

**측정:** 오선택·재입력·커서 문제·실제 완료·시각/키보드 접근성 검사. 큰 글자와 자동 검사 통과는 고령자 전체 사용성 보장이 아니다.

## 3. 확인과 자신감

**가설:** 원문 확인과 실제 값 검토, 명확한 제출 버튼이 사용자가 스스로 확인하는 경험을 돕는다.

**설계:** 안내·동의와 결과 분리, 사용자가 직접 동의, 최종 확인, 원본 복귀.

**측정:** 무엇을 제출했는지 설명할 수 있는지, 실제 설문 문항과 응답, 관찰된 도움 요청. 현재 자신감 점수·불안 감소 수치는 없다.

## 4. 서비스 운영 가치

**가설:** 완료율·문의·지원 부담이 개선되면 서비스 제공자에게 가치가 있을 수 있다.

**현재:** 기관 도입·운영 데이터 없음. 테스트 서비스의 성공을 실제 운영기관의 비용 절감으로 환산하지 않는다.

**후속 확인:** 동일 업무의 기간별 문의량·도움 투입·완료/미완료와 개선 비용. 원본 사이트 개편, 대상자 차이 같은 다른 요인도 구분해야 한다.

## 5. 기술 KPI 정의

| 지표 | 정의 | 발표 주의 |
|---|---|---|
| 작업 성공 | 원본 서비스의 최종 기록과 사용자 입력·선택이 일치 | FLECTO 성공 문구만으로 판정하지 않음 |
| 조작 가능 시간 | 목표 요청부터 검증된 컨트롤 사용 가능까지 | 빈 shell 표시 시간과 분리 |
| timeout | 준비 요청이 10초 상한에 도달 | 전체 시도에서 제외하지 않음 |
| 재사용 성공 | 후보를 현재 요소에 다시 연결하고 검증 통과 | 오래된 개인값·정원 표시를 성공으로 세지 않음 |
| 추가 계획 요청 | 준비된 현재 화면에서 이후 발생한 FLECTO 계획 요청 | 모델 내부 추론 횟수나 전체 사이트 무추론과 다름 |
| 원본 오류 보존 | 서버 거절·결과 미확인을 사용자에게 정확히 표시 | 자동 재제출·거짓 성공 금지 |
| 데이터 최소화 | 시험 sentinel이 모델·로그·캐시·광고 경로에 없는지 | 절대적 유출 0 보장으로 일반화하지 않음 |

## 6. 결과 없는 기대효과 카드 문구

- **더 쉽게 — 현재 해야 할 일을 명확하게 보여주는 것이 목표입니다.**
- **더 끝까지 — 작업 완료와 실패를 원본 결과로 확인하겠습니다.**
- **더 스스로 — 사용자가 내용을 이해하고 직접 선택하는 경험을 검증하겠습니다.**

세 카드는 같은 크기로 표시한다. 실측 값이 없는데 막대 높이나 별점으로 효과 크기를 암시하지 않는다.

## 7. 결과가 생겼을 때

[결과 양식](../evidence/01_RESULTS_TEMPLATE.md)에 기록하고 표본·모드·실패·시간 구간을 먼저 명시한다. 탐색적 참가자 체험과 고령자 대상 연구, 자동 기능 검사와 실제 사용자 효과를 따로 보고한다.
