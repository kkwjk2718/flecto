# 수익구조 — 준비 시간의 비개인화 후원에서 시작

**분류: 사용자 선택을 반영한 초기 사업 가설과 후속 후보. 실제 계약·광고 정산·가격·매출은 확인되지 않았다.**

## 1. 초기 모델

이용자에게 별도의 제품 구독료를 요구하지 않는 방향을 검토하고, 실제 화면 준비가 3초를 넘는 동안 분리된 비개인화 광고·후원 카드로 운영비를 지원한다. 해커톤에서는 정적 소재와 ‘시연용 광고 · 실제 후원 계약 없음’ 라벨로 동작을 구현한다.

카드가 표시되었다는 것과 실제 광고 네트워크에서 정산되는 노출은 다르다. 신청 내용·현재 페이지·개인 입력·사용자 연령을 광고에 전달하지 않는다.

## 2. UX와 수익의 우선순위

1. 화면이 준비되면 광고 표시 시간과 무관하게 즉시 전환한다.
2. 10초가 되면 준비 대기를 종료하며 광고도 끝낸다.
3. 닫기·취소는 광고를 보기 위한 불이익으로 만들지 않는다.
4. 반복 과업에서 빠르게 재사용할 수 있으면 광고 없이 바로 연다.
5. 현재 계획은 한 goal session에 최대 한 번의 후원 표시다.

**빠르게 만들수록 광고 기회가 줄 수 있다는 구조를 숨기지 않는다.** 대기 증가를 수익 최적화 지표로 삼지 않는다.

## 3. 돈과 가치의 흐름

| 주체 | 제공하는 것 | 받는 것 / 검증해야 할 것 |
|---|---|---|
| 이용자 | 직접 선택·입력·확인 | 별도 제품 과금 부담을 낮춘 이용 경험. 실제 사용성은 검증 필요 |
| 후원사 | 계약이 성립한 경우 후원비·광고비 | 명확히 표시된 비개인화 후원 노출. 집행 가치와 정산 조건 확인 필요 |
| FLECTO 운영자 | UI 설계·검증·재사용·지원 | 운영비 회수 가능성. 원격 추론·유지·지원 비용을 포함해 검증 |
| 원본 서비스 운영기관 | 후속 협업·도입의 후보 | 문의·중단·운영 부담 감소 가능성. 실제 도입 전 효과를 보장하지 않음 |

원본 서비스가 지금 FLECTO와 제휴했다는 의미가 아니다. 테스트 사이트는 팀이 만든 가상 서비스다.

## 4. 가능한 계약 형식

### A. 노출 기반 계약
정산 가능한 노출과 계약 단가가 필요하다. 로딩 카드가 몇 번 보였는지뿐 아니라 광고주의 조건을 만족했는지 확인해야 한다. 실제 단가·체류시간 조건을 가정해 발표하지 않는다.

### B. 기간 단위 후원
월·행사·시범운영 단위로 서비스 지원 가치와 범위를 협의하는 후속 제안이다. 짧은 로딩에서도 성립할 가능성을 검토하되, 후원사가 지불할 의사가 있다는 검증은 아직 없다. 초기 대화에서 제안한 광고 방향을 다른 확정 모델로 대체한 것이 아니다.

### C. 기관 도입·지원 계약
특정 업무의 화면 구성·변경 감지·검증·지원 범위를 제공하는 중기 후보다. 일정 사용자 수, 절감액, 가격은 아직 없다. 사용자당 무조건 과금하는 것보다 어떤 지원 책임을 맡는지 먼저 정한다.

### D. 화이트라벨·SDK
다른 서비스가 FLECTO의 화면 구성 기능을 자신의 서비스 안에 넣는 장기 후보다. 브라우저 확장과 다른 배포·권한·지원·품질 관리가 필요하다. 현재 제품 기능이나 준비된 API 상품으로 소개하지 않는다.

## 5. 단위경제성 — 공식만 준비, 값은 비워둠

다음 기호는 실제 측정값이 아니라 나중에 채울 변수다. 계산식은 같은 기간·동일 비용 기준을 사용한다.

```text
총수입 = 실제 후원 계약수입 + 정산 가능한 광고수입 + 실제 도입·지원수입
총비용 = 신규 계획·재계획 비용 + 재사용 검증·서버 비용 + 지원·기타 운영비
운영차액 = 총수입 - 총비용

노출 기반 광고수입 = 정산 조건을 충족한 노출 수 × 계약상 단가
```

후원과 광고가 동일 계약이라면 중복 합산하지 않는다. 개발에 쓴 모델 비용과 제품 운영 원가를 분리하고, 구독에 포함된 사용량을 청구액 0원인 영구 무료 자원처럼 취급하지 않는다. 현재 알려지지 않은 값은 ‘미측정’이다.

### 재사용률 변화 시 함께 볼 것

| 변화 | 가능한 효과 | 반드시 함께 측정 |
|---|---|---|
| 재사용 증가 | 신규 추론 감소 가능 | 검증·재연결 실패와 재생성 비용 |
| 대기 감소 | 더 빠른 조작 가능 | 3초 이상 준비 요청과 광고 기회 감소 |
| 사이트 범위 증가 | 적용 업무 확대 가능 | 사이트 변경·지원·QA 비용 증가 |
| 신규 모델·프롬프트 | 성공·지연 변화 가능 | 같은 과제·실패 포함 비교 |

‘사용자가 늘수록 항상 이익 증가’ 그래프를 임의로 그리지 않는다.

## 6. 도입 전 검증 질문

후원사에는 누구에게 어느 위치에서 어떤 메시지가 보이는지, 개인정보 타기팅 없는 노출에 비용을 지불할지, 정산 기준이 무엇인지 묻는다. 운영기관에는 반복 문의·이탈 상황·지원 인력·배포 책임·원본 변경 대응을 확인한다. 아직 인터뷰나 계약을 수행한 것처럼 기록하지 않는다.

## 7. 정책과 공개 배포

기존 대화·v6 자료에는 Chrome 확장 광고·사용 데이터 정책의 제약이 정리되어 있다. 이번 통합에서는 이를 재검증하지 않았다. 공개 배포·실제 정산 전에 현행 스토어 정책과 도구 이용 조건을 별도로 확인한다. 직접 후원 방식이라고 자동 승인되는 것은 아니다. [기존 광고·개인정보 명세](../spec/07_ADS_AND_PRIVACY.md)

## 8. 발표용 문장

### 약 20초
초기에는 이용자에게 별도 구독료를 요구하기보다, 실제 준비 시간의 비개인화 후원 카드로 운영비를 지원하는 모델을 검토합니다. 화면이 준비되면 광고는 즉시 사라집니다. 정산 수입이 처리비용을 감당하는지는 실제 계약과 사용량으로 검증할 계획입니다.

### 약 45초
첫 모델은 실제 로딩이 3초를 넘었을 때만 보여주는 구분된 후원 카드입니다. 광고를 위해 기다리게 하지 않고, 입력 내용이나 페이지 정보를 광고에 넘기지 않습니다. 다만 재사용으로 대기가 짧아지면 광고 기회도 줄어듭니다. 그래서 노출 기반 모델과 기간 후원을 함께 검토하고, 후속으로는 특정 서비스를 운영하는 기관의 도입·지원 수요를 확인하려 합니다. 현재는 시연 광고이며 계약·매출이 검증된 사업은 아닙니다.
