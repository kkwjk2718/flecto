# 포지셔닝과 에이전트 질문에 대한 답

## 1. 기본 포지셔닝

**FLECTO는 대신 클릭하는 에이전트가 아니라, 사용자가 직접 다룰 수 있는 인터페이스를 설계하고 원래 기능에 연결하는 런타임이다.**

이 문장은 제품의 중심 경험을 설명한다. 다른 에이전트 전체가 사용자 확인·캐시·GUI를 제공하지 못한다는 비교 주장은 아니다.

## 2. 세 가지 차별화 축

### A. 결과물이 ‘지속해서 조작하는 현재 화면’이다
목표를 이해한 AI는 큰 버튼·짧은 단계·원문 확인을 갖춘 화면을 구성한다. 사용자는 강좌나 시간을 직접 비교하고, 입력을 수정하고, 내용을 확인한 뒤 제출한다. 자동 대행이 적합한 상황도 있으며 모든 사용자가 직접 조작을 선호한다고 가정하지 않는다.

### B. 검증된 현재 화면의 반복 조작을 일반 코드로 처리한다
계획 생성 후 입력·선택·수정은 정해진 연결기로 수행한다. 페이지 구조가 바뀌거나 새 페이지가 나타나면 재분석한다. ‘전체 사이트를 영원히 AI 없이 사용’하거나 ‘모든 작업 한 번 추론’으로 표현하지 않는다.

**증명 장면:** 현재 화면의 추가 계획 endpoint만 차단하고 수정·원본 제출을 수행한다. 인터넷 전체를 끄는 것이 아니며, 실제로 관찰한 ‘추가 계획 요청 수’를 표시한다.

### C. 서로 다른 사이트에서 일관된 조작 방식을 제공한다
구매 혜택과 문화센터의 원본 구조는 달라도 FLECTO의 작업 선택·입력·동의·확인 화면은 같은 원칙을 따른다. 재사용하는 것은 공통 컴포넌트와 검증 가능한 작업 구조다. 사이트별 정답 분기로 완성 UI를 숨겨 놓지 않는다.

## 3. 비교표 — 제품군 전체의 성능 등급이 아님

| 설계 관점 | 행동 자동화를 중심으로 한 접근 | FLECTO가 선택한 접근 |
|---|---|---|
| 중심 결과 | 맡긴 작업의 수행 | 사용자가 직접 쓰는 현재 화면 |
| 선택·수정 | 제품에 따라 대화·확인·직접 개입 | 화면에 보이는 입력과 선택으로 수행 |
| 반복 이용 | 제품마다 구현이 다름 | 현재 연결 검증 후 일반 코드·구조 재사용 |
| 비교할 근거 | 같은 작업의 실제 관찰 필요 | 두 사이트 원본 결과·추가 요청 차단·변형 대응 |

‘통제 낮음/높음’, ‘접근성 없음/있음’, ‘캐시 없음/있음’으로 전체 도구를 나누지 않는다. 직접 비교시험이 없으므로 속도·비용 우승표도 만들지 않는다.

## 4. 심사위원 답변 — 20초 안팎의 원고

대신 처리하는 것이 목적이라면 에이전트가 적합할 수 있습니다. 저희는 사용자가 내용을 확인하고 직접 선택할 수 있는 화면에 집중했습니다. 준비된 화면에서는 입력이나 선택을 바꿀 때마다 AI에게 다시 요청하지 않고, 서로 다른 사이트에서도 같은 조작 방식을 제공하는 구조를 검증합니다.

## 5. 더 물었을 때 — 근거 중심 답변

핵심은 확인 버튼 하나가 아닙니다. 현재 페이지의 기능을 안전한 템플릿에 연결하고, 그 화면 안의 반복 조작을 일반 코드로 처리하며, 원본이 바뀌면 오래된 연결을 거부하는 결합입니다. 이 구조를 두 테스트 사이트와 추가 계획 요청 차단, 필수 항목 변경 조건에서 확인하는 것이 이번 목표입니다. 아직 검증하지 못한 부분은 따로 공개합니다.

## 6. 선행연구와 신규성

대화에서 Adaptive Interface·NAI·접근성 도구·웹 재작성 연구가 언급되었다. 이번 자료 정리에서는 선행연구를 새로 조사하거나 본문의 세부 비교를 검증하지 않았다. 발표에서 특정 연구와 차이를 말하려면 원문 범위를 확인해야 한다.

따라서 현재 사용 문구는 **‘방향 자체에 유사한 접근이 있으며, 이번에는 원본 기능 연결·반복 조작·검증된 구조 재사용을 제품으로 구현하고 검증하는 데 집중한다’**다. 세계 최초, 특허 독점성, 연구적 신규성 점수는 사용하지 않는다.

## 7. 광고의 위치

광고는 차별화 기술이 아니라 이용자 비용을 지원하려는 수익 가설이다. 광고가 붙었다는 이유로 에이전트와 다르다고 답하지 않는다. 3초·10초 정책과 신뢰할 수 있는 원본 연결을 먼저 설명한 뒤 사업모델을 별도 설명한다.
