# 동기·문제 정의·멘토링 반영

**근거:** 제공된 멘토링 전사 및 이후 대화의 사용자 선택. 이 문서는 제품 관련 내용만 요약한다. 멘토의 개인 경력·시장 일화·가격 추정치를 현재 사실이나 시장 통계로 사용하지 않는다.

## 1. 실제 출발점

멘토링 04:15 전후에 건우는 부모님·조부모님이 구매 혜택 신청 중 도움을 요청한 경험을 설명했다. 원본 안내에 따라 구매 번호와 여러 입력을 찾아 채워야 했으며, 직접 들어가 본 건우도 어렵다고 느꼈다는 내용이다.

이를 발표에서는 ‘가족이 구매 혜택 신청 과정에서 막혀 도움을 요청했다’고 요약한다. 실제 행사명·조건·혜택액은 별도로 검증하지 않았으므로 구체적인 기업 프로그램의 실태 조사처럼 설명하지 않는다. 가족의 말을 따옴표로 넣어 증언처럼 재구성하지 않는다.

## 2. 문제 정의

### 관찰
신청을 하려는 목적은 있었지만 메뉴·입력·절차를 스스로 진행하기 어려워 가족에게 도움을 요청했다.

### 이번에 선택한 해결 대상
**사용자가 내용을 이해하고 직접 선택할 수 있도록, 복잡한 웹의 작업 구조를 다시 보여주는 것.**

### 이번에 선택하지 않은 방향
완전한 자동 대행, 가족 대신 대화하는 메신저 에이전트, 광고를 붙인 범용 브라우저. 멘토링에서 대안으로 거론됐지만 현재 제품으로 전환하기로 결정한 것은 아니다.

## 3. 멘토링의 핵심 질문과 반영

| 질문 | 반영한 계획 | 필요한 증거 |
|---|---|---|
| 쉬운 UI라고 누가 판단하는가? | 큰 글씨만이 아니라 작업 완료·오류·도움 요청을 측정 | 실제 참가자와 조건, 성공·실패 모두 기록 |
| 에이전트가 대신하면 되지 않는가? | 현재 페이지의 직접 조작과 반복 사용 경험에 집중 | 준비 후 추가 계획 요청 차단 시연 |
| 한 번 만든 구조를 여러 번 쓸 수 있는가? | 개인값이 아닌 연결 구조만 저장·재검증 | cold/warm·무효화 결과 |
| 로그인된 상태에서 실제 기능이 이어지는가? | 원본 탭 위의 확장, 비밀번호 접근 없이 로그인 후 시작 | 원본 세션의 실제 입력·저장 |
| 누가 비용을 내는가? | 준비 중 비개인화 후원 광고를 초기 사업 가설로 선택 | 실제 계약·정산·처리비용의 향후 확인 |
| 팀 경험이 제품과 연결되는가? | 실제 구현·테스트·자원 관리 결과로 설명 | 개발 로그·동작·검증 빌드; 수상이나 역량 점수 과장 금지 |

멘토의 17:05 전후 설명은 관찰한 상황으로 돌아가 문제를 다시 좁혀 보자는 취지다. 24:23 전후에는 문제와 해결책의 여러 조합을 비교하는 방식을 제안했다. 이를 ‘아이디어를 무조건 버리라’는 결론으로 기록하지 않는다.

## 4. 발표 오프닝 3가지

### A. 실제 경험 중심 — 기본안
저희 가족은 온라인 구매 혜택을 신청하다가 어떤 메뉴로 들어가고 무엇을 입력해야 하는지 몰라 도움을 요청했습니다. 원하는 것은 신청 하나였지만, 웹사이트의 구조를 먼저 이해해야 했습니다. FLECTO는 이 경험에서 출발했습니다. 사용자가 메뉴를 배우는 대신, 필요한 선택과 입력이 사용자에게 맞게 정리되면 어떨까요?

### B. 제품 철학 중심
웹서비스에서 하고 싶은 일은 분명해도 그 일을 위한 화면은 복잡할 수 있습니다. 저희는 사람의 능력을 단정하기보다, 인터페이스가 요구하는 탐색과 해석을 줄이는 방향을 택했습니다. FLECTO는 사용자가 직접 확인하고 진행할 수 있는 화면을 만들고자 합니다.

### C. 한 줄 질문 중심
**“사용자가 원하는 것은 웹사이트를 배우는 것일까요, 아니면 일을 끝내는 것일까요?”**
FLECTO는 복잡한 메뉴 대신 필요한 선택과 입력을 단계별로 보여주는 인터페이스를 목표로 합니다.

## 5. 서론에서 말하지 않을 것

자료에 없는 인구 비율, ‘대부분의 고령자가 포기한다’는 주장, 로그인보다 입력 단계 이탈이 높다는 수치, 혜택을 실제로 잃은 금액, 대상자 인터뷰 인원은 만들지 않는다. 필요하면 조사 계획으로 남긴다.

## 6. 같은 문제를 다르게 읽는 가능성

가족의 디지털 업무 지원 부담을 줄이는 것도 가능한 문제 정의다. 다만 이번 제품의 첫 가치는 ‘가족에게 요청하지 않게 한다’는 보장보다 **본인이 직접 확인하며 완료할 수 있도록 돕는 화면**이다. 실제 도움 요청 감소는 기대효과로 측정한다.
