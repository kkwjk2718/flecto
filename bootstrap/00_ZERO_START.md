# ZERO 상태에서의 설치·환경 준비

**이 파일은 미래 실행 절차다. 지금 설치나 로그인이 완료됐다는 기록이 아니다.**

## 읽기 점검 → 승인 묶음 → 최소 설치 → 기능별 시험

첫 검사 대상은 선택한 프로젝트 폴더와 명시된 실행 도구뿐이다. 홈 전체·브라우저 프로필·Keychain·클라우드 키를 뒤지지 않는다. 기존 저장소가 있으면 현재 변경을 보존하고, 새 Git 저장소 초기화나 파일 이동 전에 충돌을 확인한다.

| 구성 | 확인할 것 | 없을 때의 정책 |
|---|---|---|
| 현재 코딩 클라이언트 | 이름·버전·로컬 파일/셸/서브작업 지원 | 클라이언트 자체는 사용자가 공식 경로로 설치·로그인해야 첫 문서를 실행할 수 있음 |
| macOS / 아키텍처 | 실제 OS·arm64, 프로젝트 경로·공백 | 이전 Windows 명령이나 경로를 가져오지 않음 |
| Git | 사용 가능 여부, Xcode 도구 stub인지 | 설치 대화창이 필요하면 한 번의 사용자 승인 항목으로 묶음 |
| Node/npm | 프로젝트 요구사항에 맞는 실제 버전 | 공식 배포의 지원 버전 설치안 제시. Homebrew·버전 매니저가 이미 있다고 가정하지 않음 |
| Chrome | 전용 시연 프로필과 확장 설치 | 개인 기본 프로필 자동화·복사 금지 |
| Playwright | 프로젝트에 고정한 패키지와 번들 Chromium | 승인된 프로젝트 설치 후 브라우저 다운로드. 설치 실패를 제품 PASS로 처리하지 않음 |
| Codex 제품 경로 | 공식 런타임·지원 로그인·출력 schema·취소 | LIVE만 차단. fixture 코드·DOM 연결 개발은 진행 가능 |
| 이미지 경로 | 실제 파일 반환 여부 | 미검증이면 DISABLED_OPTIONAL, 이미지 없이 진행 |

현재 폴더 바깥에 새 도구를 설치하거나 shell startup·전역 권한을 바꾸는 작업은 별도 승인이다. `curl | sh`, 임의 원격 스크립트, 자동 sudo·비밀번호 입력을 시작 문서에 넣지 않는다. 프로젝트 의존성은 한 작성자만 설치·잠금파일 갱신한다. lifecycle script가 필요한 의존성은 목적을 확인하고 승인된 범위에서 사용한다.

## 최초 사용자 확인을 한 번에 모으는 형식

- 현재 클라이언트로 이 폴더 안의 생성·수정·테스트를 해도 되는가?
- 필요한 공식 런타임 설치, 프로젝트 패키지·테스트 브라우저 다운로드 범위는 무엇인가?
- 현재 로그인한 개발 경로의 호출은 어디까지 승인했는가? 새 청구 계정은 제외한다.
- 제품 Codex 로그인은 사용자가 어느 시점에 수행할 수 있는가?
- 사전 코딩/환경 준비가 대회 규정에 허용되는가? 당일 시작 시각·제출 시각은 무엇인가?

이미 답이 있으면 다시 묻지 않는다. 응답은 `templates/APPROVALS.md`에 근거와 함께 옮기고, 추후 실제 `.flecto/approvals.json`을 만들 때 그 사실만 기록한다. 자격증명은 넣지 않는다.

## 최초 성공을 나누어 기록

ENV_READY: 도구와 설치를 실제 확인. DEV_READY: 승인된 개발 에이전트가 제한된 작은 변경을 실제 수행. FIXTURE_READY: 원본 테스트 사이트와 브라우저가 실제 실행. PRODUCT_AUTH_READY: Codex 로그인·지원 모델·JSON 응답 실제 확인. 이 상태들은 서로를 자동으로 의미하지 않는다.

## 스크립트를 먼저 만들게 될 때

실제 작성 후 `실행파일 존재 → 명령 도움말 → 짧은 성공 시험 → 실패 종료 시험`을 거쳐 `state/STATUS.md`의 Command Registry에 등록한다. 본 문서의 `doctor`, `resume`, `demo:start`는 아직 역할 이름이다. 없으면 만들어야 하며, 이름만 보고 실행하지 않는다.

## 루트·상태·산출물 배치

루트에 문서와 앞으로 만들 `apps/`, `packages/`, `tests/`, `scripts/`를 둔다. `.flecto/`는 승인 후 생성할 비추적 런타임 디렉터리다. 그 아래 control/state/worktrees/candidates/evidence/releases/image-jobs를 분리한다. 먼저 `.gitignore`를 만들어 DB·키·프로필·로그가 커밋되지 않게 한다. 텍스트 승인 양식과 비식별화한 상태 요약만 `state/`에 유지한다.

심볼릭 링크·기존 `.git`·상위 저장소의 지시 파일을 확인한다. 권한 밖 디렉터리로 해석되는 경로를 따라 새 파일을 쓰지 않는다. 안전 검사가 문서 수준이라면 실제 OS 격리가 검증됐다고 쓰지 않는다.
