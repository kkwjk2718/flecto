# 독립 원본 테스트 서비스 두 개

## 공통 원칙

FLECTO 없이 직접 사용해도 정상이어야 한다. 실제 세션별 저장과 오류가 존재해야 하며 원본 UI를 의도적으로 unusable하게 만들지 않는다. 메뉴가 많은 상황을 재현하되 정답이 숨어 있는 악의적 퍼즐로 만들지 않는다.

FLECTO extension과 planner는 원본 DB를 직접 읽거나 QA oracle endpoint를 사용할 수 없다. 원본 DOM에 `data-flecto-answer`, 완성된 plan, 인위적인 action 순서 정답을 심지 않는다. HTML label/required/aria 등 정상 접근성 정보는 정당한 페이지 정보다.

## A — 구매 혜택 / full page navigation

테스트 로그인→첫 화면→혜택 신청→주문번호·구매일·상품분류→안내·동의→검토→제출→접수내역. 정상 테스트 주문과 잘못된 주문, 이미 신청한 주문을 합성 fixture로 만든다. 개인정보나 실제 기업 데이터는 쓰지 않는다. 파일 첨부 없음.

변형 B는 메뉴 순서/장식 class/자동 ID/필수 입력 추가/고지 수정/다른 form의 같은 이름 버튼/서버 오류를 포함한다. 모든 변형을 fail closed로만 처리하지 말고, 공개 구조로 재분석 가능한 경우는 정상 완료도 검사한다.

## B — 문화센터 / React SPA

로그인→강좌 목록→강좌·시간 radio/select→신청자 테스트 정보→안내·동의→검토→신청→내역. 키보드 조작 가능한 일반 선택지를 쓰고 복잡한 drag/calendar는 제외한다.

controlled text, select/radio, 화면 이동, 뒤로가기, 다음 render 값 유지와 예약 직전 정원 변경을 시험한다. 최신 정원은 원본이 결정하며 캐시에 있던 값으로 확정하지 않는다. 첫 사이트의 템플릿을 공통 사용하되 source mapping은 새로 검증한다.

## 로그인 프로필

실제 시연은 별도 Chrome 프로필에 저장한 합성 테스트 계정을 원본 자동완성으로 사용한다. 인증 대화는 사람이 처리한다. 자동 E2E는 별도 Playwright Chromium 프로필과 테스트 로그인 helper를 사용할 수 있으나 그것을 Chrome 비밀번호 관리자 검증으로 주장하지 않는다. [S11–S12]

## QA oracle

QA만 가진 synthetic-run token/fixture ID로 원본 저장값과 건수를 검사한다. oracle는 제품 success를 만드는 경로가 아니다. 확장·planner에 QA token을 주지 않는다. 숨은 서버 경로가 접근 가능하면 제품 코드에서 호출하지 않는지만 보지 말고 권한도 테스트한다.

## 시연 초기화

합성 신청·강좌 정원만 되돌린다. 로그인 쿠키 유지·복원은 의도된 테스트 계정 범위에서 별도로 처리한다. Chrome password store와 개인 폴더를 지우지 않는다. QA와 DEMO는 DB 이름뿐 아니라 실행 포트·profile·token namespace도 분리한다.

## 현장 체험

심사위원에게 실제 구매나 신청 정보를 입력시키지 않는다. 합성 주문번호·선택 사례 카드를 준비한다. 관찰: 도움 요청, 오류, 작업 완료, 원본 결과 이해 여부. 인원·반복·도움 제공을 기록하고 샘플 밖 집단으로 일반화하지 않는다.
