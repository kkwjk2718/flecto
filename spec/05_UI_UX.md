# UI/UX 상세 — 고령자를 먼저 고려한 안정적인 조작

## 디자인 방향

밝은 배경, 짙은 글씨, 파란 주요 행동. 읽는 순서는 제목→짧은 설명→현재 입력/선택→주요 버튼이다. 기술 상태는 접힌 '시연 정보'에서 보되 일반 화면을 엔지니어링 대시보드로 만들지 않는다. 사용자 입력·포커스가 없는 장식 변화로 화면이 흔들리지 않게 한다.

제안 토큰: background #F7F9FC, surface #FFFFFF, text #172033, primary #155EEF. 이 값은 최종 접근성 인증이 아니라 출발값이다. 실제 조합·상태의 대비를 검사한다. 본문 기본26px/옵션22·26·30, line-height 약1.5, 주요 버튼 높이 최소56px, 읽기 영역 최대760px를 기본값으로 둔다. [S15]

## 여섯 화면의 정확한 동작

### 1. 작업 선택
제목 `무엇을 하시겠어요?`. 확인된 작업 2~4개만 먼저 크게 제시하고 추가 항목은 `다른 작업 보기`로 펼친다. `다른 일 입력하기`는 텍스트 목표 입력을 열되 개인정보를 적지 말라고 안내한다. 확인되지 않은 목적은 '찾지 못했어요'와 원본을 제시한다.

### 2. 입력 묶음
제목 `주문 정보를 입력해 주세요`. 관련 입력 2~3개, 모든 입력에 label, 원문을 기반으로 한 도움말과 `원문 보기`. placeholder만 label로 쓰지 않는다. 날짜는 키보드로도 입력 가능하게 하고 원본 허용 형식과 검증한다. 금액·기한은 새로 계산해 바꾸지 않는다.

### 3. 항목 선택
강좌·시간 등 공개 선택지를 큰 radio/card로 표시한다. 선택 상태는 색뿐 아니라 체크 표시·문장으로 표현한다. 선택하지 않았는데 첫 항목을 자동 확정하지 않는다. 원본의 기본 선택을 가져올 때도 현재 실제 값이라고 보여준다. 정원 변경 시 명확히 취소·재선택하게 한다.

### 4. 안내·동의
필수/선택을 원본대로 구분한다. 요약 위에 원문 접근을 보장한다. 체크박스는 기본적으로 원본 현재 상태를 보여주되 사용자 동작 없이 변경하지 않는다. '모두 동의'를 새로 만들어 필수·선택을 묶지 않는다. 중요한 고지를 광고 아래로 밀어 숨기지 않는다.

### 5. 최종 확인
모델이 아니라 현재 실제 값을 보여준다. 묶음마다 `수정`을 누르면 해당 단계로 돌아가고 나머지 값은 보존한다. 최종 버튼은 `혜택 신청하기`, `강좌 신청하기`처럼 결과가 분명해야 한다. `다음`이라고 위장하지 않는다. 확인 후 값이나 조건이 바뀌면 재확인한다.

### 6. 결과
원본의 실제 처리 상태와 접수 정보만 로컬로 보여준다. `완료`, `수정 필요`, `결과 확인 필요`를 구분한다. 성공 근거가 없으면 축하 화면을 만들지 않는다. 다음 행동은 원본에서 확인한 신청 내역 보기와 종료다.

## 공통 shell

상단에는 FLECTO 이름, 현재 원본 서비스의 식별 가능한 공개 이름, 원본 보기·종료를 둔다. 로그인 출처를 숨기지 않는다. 본문에는 실제 확인된 현재 단계 이름을 쓴다. 전체 단계가 아직 불명확하면 '2/5'를 만들어내지 않는다.

하단은 `이전`과 주요 행동. sticky footer를 쓰면 실제 높이만큼 본문 scroll-padding을 확보하고 200% 확대에서 버튼·오류가 가려지지 않는지 검사한다. 짧은 viewport에서는 sticky를 풀어야 할 수 있다. 아주 긴 한국어 제목·도움말·옵션도 잘리지 않아야 한다.

## 로딩과 광고 문구

0초: `사용하기 쉬운 화면을 준비하고 있어요.`
3초 초과: `필요한 입력과 버튼을 정리하고 있어요. 준비되면 바로 열어드릴게요.`
실제 연결 검사: `원래 사이트의 기능과 연결을 확인하고 있어요.`
10초 만료: `지금은 화면을 준비하지 못했어요. 원래 화면에서 계속하거나 다시 시도할 수 있어요.`
광고 라벨: `FLECTO 후원 광고` + `시연용 광고 · 실제 후원 계약 없음`.

진행률·예상 완료 시각을 꾸미지 않는다. 로딩 설명은 실제 state에서 나온다. 광고는 포커스를 가져가지 않고 닫아도 준비를 계속한다. 새 주요 버튼이 직전 광고의 클릭 위치를 대체하지 않도록 영역을 분리한다.

## 키보드·포커스·확대

Tab/Shift+Tab 순서, 명확한 focus outline, Escape 종료·원본 복귀, 오류 발생 시 첫 관련 입력으로 이동, 닫은 뒤 이전 원본 포커스 복구를 구현한다. 상태 문장은 polite live region으로 필요한 상태 전환 때만 안내한다. 100ms마다 elapsed를 읽어주지 않는다. [S16]

배경을 inert로 만들면 원본 동작 어댑터와 충돌하는지 먼저 검사한다. '모달이니 body 전체 inert'를 기계적으로 적용하지 않는다. 원본에 강한 top-layer dialog가 있으면 FLECTO가 무조건 덮으려 하지 않고 원본 계속하기로 넘길 수 있다. `aria-hidden`과 focus 상태는 원래 값을 보존·복구한다. 접근성 검사 PASS와 모든 실제 보조기기 검증은 다른 상태다.

## 한국어·데이터 보존

IME composition 중 Enter는 제출이 아니다. 조합 중 자동 검증·재배치·포커스 이동 금지. 붙여넣기·전체 선택 삭제·뒤로 이동 수정도 검사한다. 작업 도중 설정 변경은 모양만 바꾸며 입력/동의를 초기화하지 않는다. 원본 보기로 전환해도 실제 반영된 값과 미반영 초안의 차이를 안내한다.

## 시각 QA의 증거

원본 비교, 빈 상태, loading+ad, 입력 오류, review, success, timeout, 200% zoom, 긴 한국어 content를 실제 렌더해서 캡처한다. URL/title, console error, primary control 동작도 함께 기록한다. 자동 IME 이벤트 시험과 실제 Mac 한국어 키보드 입력 확인을 구분한다. 실기기 확인 전 '한글 실사용 검증 완료'로 쓰지 않는다.

심사위원·참가자의 체험 조건과 도움 제공 여부를 기록한다. 고령자 편의성의 실증으로 일반화하지 않는다.
