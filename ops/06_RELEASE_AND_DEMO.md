# 마감·정상본·시연·제출

## 동일한 릴리스의 의미

소스 SHA뿐 아니라 실제 확장/서버 artifact hash, 계약/gate/cache/prompt/model lock 버전을 묶는다. 코드나 프롬프트·모델·실행 설정을 바꾸면 관련 검증은 다시 수행한다. 파일이 완전히 같은 기존 artifact를 쓰는 경우에는 그 해시의 근거임을 명시한다.

## 제품 등급

| 등급 | 조건 |
|---|---|
| FULL_LIVE | 동일 artifact에서 원본 T01–T26와 추가 T27–T40의 요구 assertion 충족, 두 사이트 실제 cold 각3회 이상, 원본 결과 확인. 시각 보완을 포함한 전체 기능은 해당 positive 경로 검증까지 필요. 수동 Chrome/IME 상태는 별도 공개 |
| LIMITED_LIVE | 두 사이트의 DOM 기반 실제 흐름·핵심 안전은 확인했지만 시각 보완 등 계획한 추가 기능의 근거가 부족. 누락 기능·assertion을 공개하고 FULL로 표시하지 않음 |
| SINGLE_SITE_LIVE | 구매혜택 실제 연결과 관련 안전 gate·LIVE 확인. 두 번째 미완성 명시 |
| FIXTURE_ONLY | 실제 코드·원본 fixture 경로 검사. 실제 모델 완주 근거 없음 |
| UNVERIFIED | 제품 완료를 주장할 근거 부족 |
| REVOKED | 알려진 안전결함으로 출고 금지 |

미구현 vision은 `capability_status`에 기록하고 미지원 시 fail closed한다. 안전한 거부 경로만 시험한 것은 vision positive 동작 통과가 아니므로 해당 전체 기능이 미완료이면 LIMITED_LIVE 이하로 표시한다. 수동 Chrome/IME 미확인은 제품 자동 검사와 별도로 공개하고 DEMO_READY로 승격하지 않는다. 해당 기능까지 검증했다고 발표하지 않는다. 핵심 T01–T26 안전 조건을 삭제하고 FULL이라고 쓰지 않는다. 복잡한 전체검사 미충족이면 실제 등급과 남은 assertion을 적는다.

운영 등급 DOCS_ONLY/SESSION_CHECKPOINTED/MANAGED_TESTED는 위와 별개다. 발표자료만 완성된 것은 FULL이 아니다. 이전 통과본도 새 결함이 적용되면 REVOKED다.

## 마감 선택

코드 중단 뒤 새 patch를 반영하지 않는다. 검증된 높은 등급 중 안전하고 가장 최근인 artifact를 선택한다. 후보 repo 최신 HEAD와 혼동하지 않는다. 검증본이 없으면 소스·실패·한계를 보존하되 완성앱으로 위장하지 않는다.

finalize는 일반 작업 DAG의 의존성이 막혔어도 현재 근거로 실행 가능해야 한다. 근거가 없는 것을 채워 넣지는 않는다. 모델 quota가 다 소진돼도 기존 템플릿과 JSON 기록으로 릴리스 설명을 생성한다.

## 산출물 allowlist

소스·lockfile·빌드, 필요한 합성 fixture, 실행 설명, 실제 test report, 비개인 screenshot/영상, 모델/스키마 버전(비밀값 없음), 한계, demo flow, 제출 체크리스트만 포함한다.

auth.json/.env/tokens/Keychain/개인 Chrome 프로필/cookies/원문 사적 로그/실사용 입력·캡처는 포함하지 않는다. 단순 파일 확장자만으로 안전 판정하지 말고 내용 sentinel/경로 검사를 한다. 코드 archive 생성과 public 배포·제출은 별도다.

## 시연 재현

별도 시연 Chrome 프로필에 합성 계정만 둔다. 테스트 서버·planner는 검증된 빌드로 실행한다. HMR이나 candidate overwrite에 의존하지 않는다. QA와 DEMO의 DB·포트·토큰을 분리한다.

demo reset은 합성 신청·예약 상태만 초기화한다. Chrome 비밀번호 저장소나 개인 폴더를 지우지 않는다. cold/warm 조건을 명시적으로 선택한다. 외부 네트워크가 막혔을 때 fixture/replay를 보여주면 화면에 그 모드를 유지한다.

## 라이브 데모 장면

1. 구매혜택 원본 첫 화면에서 목표 선택.
2. 큰 단계형 화면에서 입력·동의·제출.
3. 원본 결과와 신청 기록 확인.
4. 준비된 현재 화면의 추가 AI 계획 endpoint만 차단하고 수정·처리.
5. 문화센터에서 같은 템플릿으로 강좌·시간 선택.
6. 원본 필수항목 변경 때 stale 연결 거부.

광고는 실제 지연일 때만 라이브로 표시한다. 지연 주입이면 fault injection이라고 밝힌다. 이미지와 오프닝 영상은 위 장면을 늦추지 않는다. 코드 모션그래픽 또는 실제 capture는 REPLAY이며 원본 LIVE 대체 증거가 아니다.

## 발표와 사업모델

에이전트가 대신 클릭하는 것과, 사용자가 재사용 가능한 일관된 화면을 직접 다루는 경험을 비교한다. 다른 도구도 갖고 있는 확인·로그인·캐시가 없다고 주장하지 않는다. FLECTO가 구현한 동작으로 말한다.

수익은 준비 중 비개인화 후원 광고의 가설이다. 최적화로 대기가 줄면 광고 기회도 줄 수 있음을 숨기지 않는다. 실제 계약·정산·수익은 확보되지 않았으면 미검증이다. 참가자 체험을 고령층 사용성 입증으로 바꾸지 않는다.

## 사람의 최종 확인

제출 파일·버전·시연 상태·행사 양식 확인은 사람이 한다. 실제 submit response가 없으면 `submitted=false`다. 기록과 패키지가 준비됐다는 것과 대회에 제출됐다는 것은 다르다.
