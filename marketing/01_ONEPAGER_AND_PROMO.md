# 한 장 소개서·부스 안내·홍보 문구

## A. 한 장 소개서 원고

### Project FLECTO
**Don’t bend the user. Bend the interface.**

**문제**
원하는 신청은 하나인데 메뉴와 입력 절차를 먼저 익혀야 하는 상황이 있습니다. 가족의 구매 혜택 신청 도움 요청 경험에서 출발해, 직접 확인하며 진행할 수 있는 화면을 만들고자 합니다.

**해결안**
FLECTO는 기존 페이지의 기능을 공통 템플릿에 연결해 큰 글씨·큰 버튼·짧은 단계의 화면으로 다시 보여줍니다. AI가 사용자를 대신해 결정하는 것이 아니라, 사용자가 필요한 선택에 집중하도록 돕습니다.

**핵심 구조**
페이지 구조 해석 → 짧은 UI 연결 계획 → 필수 항목·원문·대상 검증 → 직접 입력·동의·제출 → 원본 결과 확인.

**시연 목표**
구매 혜택 신청의 구조 변형에 대응하고 문화센터 강좌 신청으로 확장합니다. 두 사이트는 가상 테스트 서비스이며, 현재 구현 상태에 따라 실제 시연 또는 계획으로 구분합니다.

**검증할 차별점**
준비된 현재 화면의 입력·수정·제출에서 추가 계획 요청을 줄이고, 같은 조작 방식을 두 사이트에 적용하며, 원본이 바뀌면 오래된 연결을 거부합니다.

**사업 가설**
실제 준비가 길어질 때 표시하는 비개인화 후원 카드로 이용자 비용을 지원하는 방향입니다. 후속으로 기관 도입과 서비스 내장형 SDK를 검토합니다. 실제 계약·정산은 아직 미검증입니다.

**현재 상태**
문서·구현 계획 준비. 실제 시연일에는 검증 빌드·지원 기능·제한사항을 별도로 표시합니다.

**체험**
행사장 팀 기기에서 합성 테스트 계정으로 체험하는 방식입니다. 공개 가입·무료 서비스 출시가 완료되었다는 안내가 아닙니다.

## C. 행사 소개 게시글 — 공개 전 승인 필요

Project FLECTO를 준비하고 있습니다. 복잡한 웹사이트를 큰 글씨·큰 버튼의 단계형 화면으로 재구성해, 사용자가 직접 내용을 확인하고 진행하도록 돕는 프로젝트입니다.

이번에는 가상의 구매 혜택 신청과 문화센터 강좌 신청을 중심으로 원본 기능 연결·작업 구조 재사용·오류 처리를 검증합니다. ‘대신 눌러주는 AI’보다 ‘직접 사용할 수 있는 화면’에 집중합니다.

현재 공개 서비스 출시가 아니라 해커톤 프로젝트입니다. 실제 구현 상태와 확인한 결과는 시연 자료에서 구분해 소개하겠습니다.

## E. 랜딩 페이지 섹션 문안

1. **Hero:** 복잡한 웹을, 직접 다룰 수 있는 화면으로.
2. **Problem:** 원하는 일과 웹사이트의 메뉴 구조 사이에 있는 간격.
3. **How:** 페이지 이해 → 템플릿 연결 → 검증 → 사용자의 직접 조작.
4. **Demo:** 같은 과제의 원본과 실제 FLECTO 화면. 미구현이면 개념도라고 표시.
5. **Why:** 준비된 화면의 반복 조작, 일관된 조작 방식, 원본 변경 검증.
6. **Status:** 지원 범위·LIVE/FIXTURE/REPLAY·빌드 검증 상태.
7. **Business:** 실제 준비 시간의 비개인화 후원 가설.
8. **CTA:** 행사장 팀 기기에서 시연 확인. 공개 URL이나 등록 버튼은 실제 제공할 때만 추가.

임의 도메인·QR·이메일·다운로드 주소를 만들어 넣지 않는다. 실제 공개 결정 전에는 연락처 수집 폼·결제·원격 접속을 붙이지 않는다.
