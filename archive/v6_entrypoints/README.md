# Project FLECTO — 빈 폴더에서 시작하는 개발 지침 v6

**작성: 2026-09-28 · 형식: Markdown 전용 시작 패키지 · 상태: DOCS_READY / 구현·설치·실행 NOT_RUN**

이 폴더는 아직 개발 환경을 설치하지 않은 사용자를 위한 시작 문서다. 설치 프로그램, 실행 중인 에이전트, 완성된 FLECTO 앱, 실행 가능한 감독자는 포함하지 않는다. 문서를 만든 환경에서 내용·링크·작업 의존성을 검사한 것과 사용자 Mac에서 제품을 실행한 것은 다르다.

## 사용자가 할 일

1. 압축을 풀어 **이 파일과 `AGENTS.md`가 들어 있는 폴더**를 앞으로 사용할 프로젝트 폴더로 둔다. 기존 파일이 있는 폴더에 무조건 덮어쓰지 않는다.
2. 사용할 코딩 에이전트 클라이언트를 정상적으로 설치·로그인하고 이 폴더를 연다. 특정 회사·모델·유료 플랜은 이 문서가 지정하지 않는다. **MD 파일만으로 아직 설치하지 않은 클라이언트가 스스로 켜지지는 않는다.**
3. 아래 시작 문장을 전달한다. 처음에는 현재 폴더 점검과 필요한 승인 목록을 묶어서 받는다. 이후 승인한 로컬 작업은 매번 묻지 않고 진행하도록 설계했다.

```text
00_START_HERE.md와 AGENTS.md부터 읽어라. 아무것도 설치·실행됐다고 가정하지 마라.
현재 사용할 수 있는 도구와 이 폴더 상태를 먼저 확인하고, 설치·로그인·지출·대회 규정에서
내가 확인해야 하는 것만 한 번에 정리해라. 개발 모델은 현재 내가 선택한 모델을 사용하고
다른 모델·계정으로 임의 전환하지 마라. 사전 준비와 당일 개발의 허용 범위를 구분해라.
그 뒤 내가 승인한 범위에서 작업표에 따라 구현·검증·수정·출고를 계속 진행하고,
막힌 경로와 독립된 작업은 계속해라. 하지 않은 실행이나 검증을 완료했다고 쓰지 마라.
```

이미 클라이언트·로그인·권한·행사 준비 범위를 확인했다면 그 결과를 실제 시작 메시지에 함께 알려 준다. 파일에 미리 적힌 `UNKNOWN`·`PENDING`을 근거 없이 승인으로 바꾸지 않는다.

## 세 가지 AI 역할을 혼동하지 않기

- **개발 AI:** 모델 미지정. 시작한 클라이언트와 사용자가 승인한 모델을 탐지·기록한다.
- **제품 AI:** 앞서 합의한 서버 측 Codex 런타임을 유지한다. 제품 모델 ID는 실제 계정의 기능·작은 시험 결과를 보고 기록한다.
- **선택 이미지 제작:** 개발 중 필요한 에셋만 사전 검증한 이미지 경로로 위임한다. 기본은 기존 Codex 경로를 확인하되 특정 모델명은 강제하지 않는다. 미준비이면 기본 도형·텍스트 에셋을 사용한다.

## 실제 진행 상태

현재 제품·운영 검사는 전부 `NOT_RUN`이다. `state/`는 시작 기록용 양식이다. 미래에 만들 `ops:*`, `demo:*`, 감독자 명령은 먼저 구현하고 실제 실행해 확인해야 한다. 지금 터미널에 붙이면 작동하는 명령으로 안내하지 않는다.

이번 패키지는 사용자 Mac이나 노션을 변경하지 않았다. 이전 ZIP 없이도 계획을 이해할 수 있도록 본문을 다시 정리했다. 원본 명세는 `archive/`에 분리 보존했다.
