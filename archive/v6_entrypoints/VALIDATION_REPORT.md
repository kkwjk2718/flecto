## 검사 방법과 한계

파일 목록·확장자·UTF-8·심볼릭 링크·활성 문서의 상대 링크를 프로그램으로 확인했다. 작업표의 실제 Markdown 표에서 40개 ID와 의존성을 읽어 DAG를 검사했다. 제품 검사표의 T01–T26 조건과 통과 문구를 제공된 v5 ZIP의 기록과 비교했고, 보존한 원문3개의 바이트 해시를 원본과 대조했다. 활성 문서의 JSON 예시3개와 코드 fence, 모델 고정 문자열 여부를 검사했다.

보존용 `archive/`의 옛 패키지 상대 경로는 원문의 일부라 새 실행 경로로 검사하지 않았다. 옛 명령·모델·테스트 결과가 현재 활성 사양에 섞이지 않도록 별도 README와 변경 기록을 뒀다. 외부 링크는 출처의 주소이지 모든 문서의 영구 가용성을 보장하지 않는다.

이 정적 검사는 계획의 실현 가능성·일정 내 완주·코드 보안·사용성·모델 정확도를 증명하지 않는다. 실제 실행기·프로세스·권한·브라우저·수용 테스트가 구현되어야 별도 검증이 가능하다. 토큰 모양 검사도 완전한 비밀정보 탐지기가 아니다. 파일 명세와 지시문은 OS 권한 격리가 아니다.
